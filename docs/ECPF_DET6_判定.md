## 一、前置定義與上下文

### 名詞

| 名詞 | 意思 |
|---|---|
| 警報 | 系統判定發生漂移並回報的那一步 |
| GT | 串流附的漂移標準答案。每個漂移有起點 `d_s` 和終點 `d_e` |
| 過渡期 | `d_s` 到 `d_e = d_s + w`。過渡期內第 t 筆以 `(t − d_s) / w` 的機率取自新概念，否則取自舊概念 |
| 過渡寬度 w | 4000、8000 或 16000 步。一種寬度是一個 cell |
| 主窗 | `[d_s, d_e + 1000]`，含端點，也就是整個過渡期再加 1000 步 |
| 短窗 | `[d_s, d_s + 1000]`，也就是 DET3 到 DET5 的主窗 |
| 命中 | 一個 GT 的窗內至少有一次警報，每個 GT 最多算一次 |
| 誤報（FP） | 落在所有窗之外的警報數。窗變長時，原本算誤報的警報可能變成命中 |
| 碰運氣的期望命中（C） | 假設警報和漂移無關、以該次執行自己的誤報率隨機出現時，預期會落進窗內的 GT 數。窗越長，C 越大 |
| 超額命中（X） | 命中數減 C |
| 平均偵測延遲（MDT） | 被命中的 GT，從起點 `d_s` 到窗內第一次警報的步數，取平均。在主窗下，它包含過渡期還在進行的那段時間 |
| 整條串流準確率 | 每筆先預測再學習，所有可計分預測中正確的比例，以可計分預測數加權合併 |
| trial | 同一個 cell 以不同亂數產生的第幾條串流。g00–g39 判定，g49 只用在閘門 G3 |
| 超出碰運氣 | 一組在一個母體上的 X 合計，95% CI 下界大於 0 |
| 可判定性 | 一個母體上至少一組超出碰運氣。兩組都沒有超出碰運氣時，P2 記「不可判定」，結論只依誤報寫 |
| 警告、確認、逾時關閉、離區關閉、參照切換、串流結尾未關閉 | 和 [DET5 判定](ECPF_DET5_判定.md)第一節相同 |
| 訓練暫停步數 | 處於警告狀態、主模型沒有學習的總步數。兩組在警告期間都暫停訓練 |

警報、GT、命中、FP、C、X、MDT、準確率的計分函式和 DET1、DET3 到 DET5 相同，都在 `scripts/analyze_det3.py`。本輪的 `scripts/analyze_det6.py` 對每條串流把長窗設成 w + 1000 當作主窗，可判定性用 `scripts/analyze_det5.py` 的同一個函式。

### 變因

- **自變因：** 偵測方式，在兩種學習器上各比一次。
  - **DET6-E** = preset `e10bft`（單棵樹）、**DET6-EF** = `det4_e10bft_hf10`（10 棵樹森林）。兩個 ADWIN 讀凍結參照模型的損失，另加只認「變差」的 leader 守衛；警告超過 1000 步沒有確認就關閉。
  - **DET6-H** = `det1_zone_hddm_a_lw0`（單棵樹）、**DET6-HF** = `det4_zone_hddm_a_lw0_hf10`（森林）。HDDM-A 的 warning 區開警告，drift 區確認，MOA 預設參數。
  - 單棵樹兩組的 preset 從 DET3 登記（`d161895`）以後沒改過，森林兩組從 DET4 登記（`fc1298d`）以後沒改過。
  - 下文的 E、H 指同一種學習器上的兩組。
- **判定用的依變因：** FP 和 X 用在主判定、次要判定、H2；準確率用在 H3。
- **只描述的依變因：** 命中、MDT、kappa、警告的開啟與關閉次數、訓練暫停步數、執行時間。
- **控制變因：** ECPF 嚴格替換、ECPF 淘汰規則、模型池上限 10、暖機 200 筆、警告期間暫停訓練、`river==0.21.2`、同一個 commit、同一台機器。沒有調任何參數。

- **產生器：** `scripts/generate_det6_streams.py`，本輪新寫。

### 判定規則（登記時固定）

- **P1 誤報：** `ΔFP = FP(E) − FP(H)`，母體內合計。95% CI 上界小於 0 記「成立」，下界大於 0 記「不成立」，其餘記「持平」。
- **P2 超額命中：** `ΔX = X(E) − X(H)`，母體內合計。CI 下界大於 0 記「成立」，上界小於 0 記「不成立」，其餘記「持平」。
- **CI：** 以串流為單位、兩組配對、有放回抽樣 10,000 次，種子 `20261012`，取第 2.5 和 97.5 百分位。依過渡寬度分三層，各層 40 條，在層內抽樣後合計。各組自己的 X 的 CI 用同一批抽樣算。
- **結論：** 兩項都成立是「優於」，兩項都不成立是「不如」，一項成立、一項不成立是「有得有失」，任一項持平就是「持平」。
- **可判定性：** 兩組在一個母體上都沒有超出碰運氣時，P2 記「不可判定」，結論改寫成「兩組的偵測都接近碰運氣；誤報 E 較少、較多或持平」。
- **主判定：** 單棵樹，120 條，主窗。
  - 範圍限於「合成 RandomRBF 資料、線性過渡 4000 到 16000 步、單棵 Hoeffding Tree、警告期間暫停訓練」。
  - 如果 P2 成立而準確率較差，要和 H3 一起寫成「抓得較多、準確率較差」。
- **兩個次要判定：** 同一套規則。
  1. 森林，120 條，主窗。
  2. 單棵樹，120 條，短窗。
  - 次要判定不改變主判定。和主判定方向相反時，兩邊都保留、都寫出來。
- **H2 各過渡寬度：** 單棵樹在每種寬度各 40 條上分開算 `ΔX`，用主窗。CI 下界大於 0 記「主方法較多」，上界小於 0 記「主方法較少」，其餘記「沒有差別」。森林也分寬度算，只描述。
- **H3 準確率：** `Δacc` 是兩組整條串流準確率的差，每次抽樣重算。CI 全正記「較好」，全負記「較差」，其餘記「持平」。在主判定和兩個次要判定的母體上各算一次。

## 二、背景與動機

**問題。** DET3 到 DET5 的四個主判定，都在 1000 步的窗內比，漂移的過渡期都在 2500 步以內。四個母體上，E10bFT 的超額命中都比 HDDM-A 少，ΔX 的 CI 都整段在 0 以下。這說明在快的漂移上，主方法抓得比較慢、比較少。但主方法的凍結參照模型，原本是為了看出慢慢變差的情況而設計的，所以還有一種可能沒有測過：漂移本身很慢的時候。

**為什麼要另開一輪。** 2026-10-14 有一次沒登記的探索檢查，用 Joe 的 3 條慢速漸變開發串流（過渡寬度 4000、8000、16000，共 26 個漂移），窗是整個過渡期加 1000 步。結果是主方法抓得比較多：森林 25 對 13，單棵樹 24 對 17。但只有 3 條、沒有 CI，資料在設計時看過，而且準確率是 HDDM-A 比較高。所以本輪用新產生的串流和事先定好的規則，回答「過渡期是 4000 到 16000 步時，E10bFT 的偵測有沒有比 HDDM-A 好、代價是什麼」。

**登記時已經知道的事：** DET1 到 DET5 的全部結果；E9 和 2026-10-14 開發檢查的結果；g49 三條的列數、GT 位置和類別筆數；本機空跑時單棵樹兩組的執行時間。

**登記時不知道的事：** 四組在 g00–g39 任何一條上的結果；兩組在線性慢速過渡上的表現。

**事前預測（登記時寫下）：**

- **主判定：** P2 成立、P1 持平，所以結論是「持平」，但 P2 單項成立。
- **森林：** 同主判定。
- **短窗：** 不可判定。
- **H2：** 寬度越大，ΔX 越大；`w16000` 是「主方法較多」。
- **H3：** 單棵樹和森林都是 E 較差。

**登記的程序。** 使用者 2026-10-18 同意由登記人提出產生器、學習器和計分窗，並要求寫完直接開跑，所以預註冊在登記前沒有經過使用者逐條審閱。這一點在預註冊第二節已經寫明。

### 4.7 事後觀察（登記後才想到，不是判準）

- **兩組都抓到九成以上，差別在少數漏掉的漂移。** 在主窗下，單棵樹的主方法命中 360 個中的 358 個，HDDM-A 341 個。森林上是 353 對 341。所以結論對少數幾個漏掉的漂移和誤報很敏感。
- **HDDM-A 的漏網集中在最慢的漂移。** 兩種學習器上，HDDM-A 在 `w16000` 都只命中 120 個中的 104 到 105 個，在另外兩種寬度是 117 到 120 個。主方法在三種寬度都是 117 到 120 個。這符合「凍結參照適合看慢慢變差」的設計想法，但本輪沒有能直接驗證這個機制的設計。
- **在慢的漂移上，主方法反而比較早。** 主窗下的 MDT，主方法在兩種學習器上都比較短。DET3 到 DET5 是主方法比較晚。可能的原因是 HDDM-A 在誤差緩慢上升時較晚進入 drift 區，但沒有拆開驗證。
- **森林讓 HDDM-A 變得很安靜，主方法的誤報幾乎沒變。** HDDM-A 的誤報從單棵樹的 169 降到森林的 33，警告開啟數從 5,738 降到 3,605；主方法的誤報從 111 降到 84。在主窗很長時，碰運氣的期望命中對誤報很敏感：森林 `w16000` 上，主方法多命中 14 個，但 C 也多了 19.26，所以 X 反而較少。森林上的結論翻轉，主要來自 HDDM-A 的誤報變少，而不是主方法抓得變少。
- **準確率較差可能和訓練暫停有關。** 主方法的訓練暫停步數是 HDDM-A 的 3 到 4 倍，準確率在兩種學習器上都較差，而且在 `w16000` 差得最多。這只是相關，沒有測過因果。
- **執行時間比預估長。** 登記時估計約 3 到 4 小時加上閘門 30 分鐘，實際從開始到計分是 5 小時 37 分。森林兩組每條約 13 到 15 分鐘（12 個平行，加上 node2 上的其他工作）。判定規則沒有用到時間，不影響任何結論。

## 五、局限性與衍生問題

**局限：**

- **合成資料：** 只有一種產生器（RandomRBF，4 類），線性過渡，每條 3 個漂移，每次都換成新概念。結論不能直接推到真實資料或其他過渡形狀。
- **結論依學習器而定：** 單棵樹上優於，森林上不如。不能寫成「在慢速漸變上主方法優於 HDDM-A」而不註明學習器。
- **主窗是依開發檢查選的：** 主窗用整個過渡期加 1000 步，是因為開發檢查在這種窗下看到主方法的優勢。窗的長度登記前就固定了，C 也會懲罰長窗下的誤報，但選窗的理由本身來自看過的資料。
- **命中接近上限：** 兩組都抓到九成以上，結論對少數漂移敏感。
- **寬度只有三種，** 都在 4000 步以上，本輪沒有 1000 步的對照。
- **主方法看過這類資料：** 主方法在 E 系列發展時用過同一類 RandomRBF 資料。
- **登記前沒有經過使用者審閱：** 預註冊由登記人依建議寫成後直接提交執行。
- **登記檔的新項目只在本機分支上，** 合併到 main 之前要先和 Joe 確認。
- **沒調參：** HDDM-A 用 MOA 預設參數，主方法的參數是在別的資料上定的。

**衍生問題：**

- 森林上 HDDM-A 為什麼變得這麼安靜，而主方法的誤報幾乎沒變？這決定了學習器換掉之後結論會不會翻轉。
- 主方法較高的訓練暫停，是不是準確率較差的原因？
- 在真實資料的慢速漂移上，結果還成不成立？

**下一步（都還沒做）：**

1. **論文的偵測主張可以這樣寫：** 在 1000 步窗內，主方法在 DET3 到 DET5 的四個母體上都抓得較少、較晚。在過渡期 4000 到 16000 步的合成慢速漸變上，單棵樹的主方法抓得較多、誤報較少，但準確率較差；換成森林則不如 HDDM-A。
2. **拆開森林翻轉的原因：** 用本輪已有的逐條分數，看兩組誤報在各條串流上的分布。這不需要新的執行，但是事後分析，只能當開發證據。
3. **測訓練暫停和準確率的關係：** 在同一類串流上讓兩組都在警告期間繼續訓練，看準確率差距會不會消失。這要用新的 trial（例如 g40–g48）並先登記。
4. **真實資料的慢速漂移：** 找有 GT、過渡期長的真實資料，例如 INSECTS 的漸增或漸變串流，再登記一輪。
