## 2. 背景:為什麼原本跑不動

實測(非推論)確認的阻斷點:

| Backend | 多類別 | 連續目標 |
|---|---|---|
| `linear` / `nonlinear` | `ValueError: classes=array([0,1])` 寫死 † | `ValueError: Unknown label type` |
| `xgb` | `label must be in [0,1] for logistic regression` | 同左 |
| `gru` | 單輸出 + BCEWithLogitsLoss | 同左 |
| `elastic` | **不 crash,靜默算錯**(acc 鎖在 0.640,永遠預測不出 class 2) | 同左 |
| `rf` / `ht` / `hf` | 可用 | 無迴歸模型 |

† 這一項的實際根因比表面更深,值得記錄:類別集合是被 `ECPFMetaLearner.on_drift()` 鎖定的。它在漂移當下對 warning buffer 呼叫 `fit()`,而 buffer 長度可能只有 **1** —— sklearn 於是把 `classes_` 定死成那單一標籤且永遠無法擴充。`SGDClassifier` 直接報 `The number of classes has to be greater than one`;`GaussianNB` 不報錯,但之後每個其他標籤的樣本都被靜默丟棄,而且這個殘廢的估計器會透過 `_compare_classifiers` 的 leader swap **傳染給主模型**。修法是從 `TaskSpec.classes` **宣告**完整類別集合,而不是從到達順序推斷。

另外三個任務相依的假設藏在共用路徑裡:

1. **誤差語意。** `abs(y_true - y_pred)` 把類別索引當序數 —— class 0 誤判成 class 3 記成誤差 3.0。二元下恰好等於 0-1 loss 所以沒人發現。
2. **UQ 提取。** `mi_like` / `predictive_entropy` / `vote_disagreement` 都是機率單體上的泛函,迴歸沒有對應物。只有 `variance_eu`(跨成員變異)能轉移。
3. **ECPF 概念等價。** 誤差 bitset 的 XOR 把「同時答錯但錯到不同類別」算成一致。K=2 下無害(二元答錯必然預測同一個另類),K>2 下會合併掉行為不同的概念。

再加上:**連續目標不會被拒絕,而是被當成 1200 個類別**去建分類器 —— 沒有錯誤、沒有警告,只有接近 0 的準確率和 20–700 倍的執行時間。

## 3. 架構:task-aware 層

新增 [`src/task.py`](../src/task.py) 作為單一契約,取代在各處加 `if regression:`。

```
TaskType          BINARY / MULTICLASS / REGRESSION
TaskSpec          .loss(y, ŷ) → [0,1]   .is_classification / .is_regression
ErrorNormalizer   線上 |殘差| → [0,1](Welford + mean±3σ,River ARFRegressor 的作法)
FrozenNormalizer  唯讀視圖,讓多個消費者共用同一尺度而統計量每 instance 只前進一次
infer_task(y)     整數且相異值 ≤ 50 → 分類,否則迴歸
```

`ConceptDriftPipeline._bind_task()` 在**任何 fit 之前**解析任務,因此可以安全地重建 backend 與 ECPF。它同時負責:

- backend 不符時替換(分類器遇到連續目標 → 退回 `htr` 並警告)或拒絕(迴歸器遇到分類目標 → 報錯)
- 擋掉統計上無效的偵測器 —— DDM/RDDM/HDDM_W/EDDM 的 `sqrt(p(1-p)/n)` 需要 Bernoulli 誤差率
- 擋掉需要機率矩陣的訊號模式

**設計上的關鍵決定:誤差每個 instance 只計算一次**,再傳給 `StreamBuffer.append`。迴歸 loss 是有狀態的(推進線上正規化器),重算會讓統計量每步前進兩次。這個 bug 在整合時真的發生了,被端到端測試抓到。

## 4. 實驗流程(可重現)

```bash
# 1. 產生合成串流(repo 內沒有任何多類別或迴歸資料)
python scripts/generate_task_streams.py --n 20000

# 2. 確認任務判定與可用 backend
python scripts/inspect_dataset.py data/synthetic_multiclass

# 3. 跑實驗矩陣
python scripts/run_task_matrix.py --out-dir outputs/task_matrix --max-steps 20000
```

**資料。** 9 條合成串流:多類別 K∈{3,5} × {sudden, gradual, recurring},迴歸 × 同樣三種漂移型態,每條 20,000 筆、3 個特徵。漂移方式是**改變哪些特徵驅動目標**,所以邊際特徵分布不變 —— 是真正的概念漂移而非共變量偏移。外加 1 條既有二元串流作為對照。

**計分口徑。** 沿用專案既有函式(`src.metrics.compute_correct_detection` 與 `run_ecpf_uq_experiment` 的 delay / false-warning-rate),不自己重寫,否則會與批次報表悄悄分歧。ground-truth 是零寬區間如 `(5000, 5001)`,偵測器不可能正好在那一步觸發,因此套用 `build_perturbation_intervals(extension=1000)` —— 與 `run_ecpf_recurring.py` 回報的口徑一致。

**驗證閘門。** 每次改動後重跑:

```bash
python -m pytest tests/ -q --continue-on-collection-errors   # 46 passed, 1 pre-existing error
python run_ecpf_recurring.py --csv data/recurring_drift/recurring_sud_sea100k_g00.csv \
    --warm-start 200 --signal-mode detector --max-steps 16000 ...
```

二元閘門比對三種訊號模式(`detector` / `meta_ecpf_gddm` / `meta_ecpf_hier_parallel`)的事件 CSV **SHA256**。單元測試無法偵測誤差語意的改變(`preprocessing.py` 原本零覆蓋率),所以雜湊比對才是真正的迴歸閘門。

## 5. 結果

### 5.1 相容性

47/47 執行完成,零 crash。多類別與迴歸都能端到端跑完整條管線,包含 ECPF 模型池、對決與事件報告。

**兩個公開入口一致。** 管線有 `run_stream()` 與 `warm_start()` + `step()` 兩條路(repo 自己的 `test_integration.py` 用的是後者)。四種標籤配置 × 4 個 backend × 2 個入口 = 32 組,結果**完全相同**,且每個 backend 都預測出全部 K 個標籤:

| 標籤配置 | `linear` | `nonlinear` | `ht` | `rf` |
|---|---|---|---|---|
| K=3 `{0,1,2}`(基線 0.333) | 0.873 | 0.822 | 0.604 | 0.865 |
| K=5 `{0..4}`(基線 0.200) | 0.585 | 0.617 | 0.641 | 0.752 |
| K=3 `{10,20,30}` | 0.873 | 0.822 | 0.604 | 0.865 |
| K=4 `{2,5,9,13}` | 0.689 | 0.762 | 0.691 | 0.815 |

非連續標籤也正確處理 —— 類別是以**在類別集合中的位置**索引,不是用 `int(label)`。

### 5.2 多類別偵測品質(6 條串流)

| backend | 平均事件數 | TP | FP | **CD%** | 準確率 | 秒/20k |
|---|---|---|---|---|---|---|
| `ht` | 16.5 | 3.0 | **11.0** | **0.0** | 0.775 | 4.6 |
| `rf` | 10.2 | 3.3 | 3.5 | 13.3 | **0.870** | 51.7 |
| `hf` | **3.4** | 1.3 | **1.4** | **14.6** | 0.615 | 33.8 |

- **`ht/error` 在多類別上不可用** —— 平均 11 個假陽性,CD 全數為 0。它對每個小波動都觸發。
- **`hf` 偵測品質最好**(最少事件、最少 FP、最高 CD),但準確率最低 —— 因為它是刻意不帶內部漂移處理的。
- **`rf` 準確率最好**,但那是 ARF 內建的 per-tree ADWIN 在適應,不是外部偵測器的功勞。**這是解讀時的混淆因子。**

單點最佳:`mc3_recurring` + `hf/error` → **CD 100%**(5 TP,0 FP)。

### 5.4 訊號對漂移的反應(關鍵發現)

> **更正(2026-08-10):** 本節初版寫「ADWIN 偵測的是上升」。直接驗證(對 river ADWIN 餵 0.5→0.1 的下降流,175 步內觸發)後確認它是**雙向**的。「往下走所以看不見」的機制說法撤回;正確的說法是**位移幅度**:機率式 UQ 訊號的位移(0.2–0.5 sd)遠小於誤差訊號在被成功偵測的漂移點上的位移(1–2.5 sd)。下方表格的量測數據本身不受影響。

所以問題不是門檻調得夠不夠好,而是:漂移後訊號的位移幅度相對於噪音夠不夠大?

```bash
python scripts/measure_signal_response.py
```

以 ground-truth 漂移點為中心,前 1500 / 後 1000 筆為窗(漂移點兩側各留 100 筆 guard band),以漂移前標準差為單位。注意 `extract_signal` 每個 instance 被呼叫**兩次**(warning 與 drift 各一),量測時只取每個 timestamp 的第一次 —— 否則序列長度加倍,索引會與漂移點差兩倍:

| mc3_sudden | `hf` | `uq_variance` | 0.2010 | 0.1762 | −0.0248 | **−0.27** |

| 訊號 | 漂移數 | 平均 shift | 中位數 | **往上的比例** |
|---|---|---|---|---|
| `error` | 9 | **+0.320 sd** | +0.347 | **89%** |
| `uq_variance` | 9 | −0.163 sd | −0.191 | 44% |

需要區分兩件事:

- **多類別上,UQ 訊號往錯誤方向移動【2026-08-10 加限定:在特徵遮罩的森林上】。** `uq_mi` 在 7 個漂移點中只有 1 個(14%)是上升的。**配對重現(§12)顯示此現象是遮罩條件性的**:同樣的串流與漂移點,無遮罩(`max_features=None`)下 `uq_mi` 翻為 +0.343 / 80% 上升,六條 3 特徵串流無一例外;10 特徵 RBF 上未翻正。本表的量測(遮罩 sqrt 配置)數據不變。
- **迴歸上,`uq_variance` 方向是對的但幅度極小**(+0.09 sd,對比誤差的 +0.28 sd)。所以迴歸是靈敏度問題,多類別(遮罩配置)是方向性問題 —— 兩者需要不同的處方。

**解讀(2026-08-10 更正 —— 初版解釋已被自身實驗推翻)。**

> ~~初版說法:漂移後所有樹「一致地錯」,分歧因而下降。~~ 直接量測裸集成的內部狀態後,漂移後兩兩**標籤**一致率是**下降**的(0.61 → 0.36),信心度也下滑 —— 與該說法相反。已撤回。

真正的分界線是**機率空間 vs 標籤空間**。四種條件(兩條串流 × 有無管線)的量測:

| UQ 模式 | 建立於 | 漂移後方向 |
|---|---|---|
| `vote_disagreement` | 硬投票 | **全部 4/4 上升** |
| `mi_like` | 機率分布 | 3/4 下降 |
| `variance_eu` | 機率分布 | 3/4 下降 |

**機制:樹在漂移後「變平」,不是「變一致」。** 葉節點統計被新舊概念混合汙染,每棵樹**個別地**變得更不確定,輸出分布趨於平坦(信心度實測 0.657 → 0.482)。這同時造成兩個相反效果:

- `mi_like = H(p̄) − avg H(p_m)`:各樹個別熵上升 → **被減項變大** → 整體下降
- `variance_eu`:所有樹往均勻分布靠攏 → 機率向量**彼此更接近** → 跨樹變異下降
- `vote_disagreement`:分布變平使 argmax 不穩定 → 硬投票四散 → **上升**

五項獨立量測相容:個別信心↓、標籤一致率↓、`vote_disagreement`↑、`mi_like`↓、`variance_eu`↓。

**這推翻了本檔開頭引用的選型理由。** `uq_extractor.py` 把 `mi_like` 選為主要模式、把 `vote_disagreement` 評為「較粗糙,硬投票丟失了機率資訊」。**被丟失的那部分機率資訊,正是漂移後往錯誤方向移動的部分。** 硬投票的粗糙在此是優點。

**未解釋的例外:** `joe rbf4` 的裸集成條件下 `mi_like` 上升(+0.63),與其餘三種相反。該串流觀測範圍內僅 2 個漂移點,樣本過小;RBF 質心移動與本專案合成串流的特徵權重輪替屬不同幾何。需更多漂移點才能判斷。

這解釋了矩陣裡的數字:UQ 設定平均只觸發 1.2 次(誤差設定 10.9 次),多數情況 0 事件 → 模型從不適應 → 準確率崩到 0.47–0.66。

## 6. 發現與建議

**1. 誤差訊號轉移得很好,UQ 訊號沒有。** 兩種新任務型態上,正規化誤差都是可用的漂移訊號。UQ 那條路在**結構上**接通了(`variance_eu` 是唯一有迴歸對應物的模式,已實作並驗證非常數),但**靈敏度不足以驅動偵測**。

**2. UQ 訊號在多類別上不是可用的主要觸發。**(2026-08-10 依五實驗系列二度更新 —— 本項初版建議調門檻、二版建議換 `vote_disagreement`,**兩者均已被實驗推翻**。)`vote_disagreement` 方向正確(4/4 上升)但平時水準就高(~0.30),漂移只多 8%,六條合成串流合計僅觸發一次;`mi_like`/`variance_eu` 位移過小(0.2–0.5 sd)。逐一掃描後,UQ 模式、樹數、δ、暖機**均非槓桿** —— 誤差訊號仍是唯一穩定可用的主要觸發,`vote_disagreement` 定位為高精確率輔助訊號。實測有效的改動有二:**警告逾時**(`ecpf_detector_warning_timeout`,預設 0=關;修過期警告污染時間戳與跨概念重用緩衝的缺陷,建議 3000)與**漂移確認後的偵測器冷卻期**(`ecpf_detector_cooldown`,預設 0=關;壓「餘波」型 FP,漂移疏用 1000–1500、密用 500 或不用)。方向閘門(`ecpf_drift_direction_gate`)三版迭代後關線,僅保留為 sudden 型串流的實驗選項。「隔離認知不確定性」的選型理由仍待重新檢視。完整診斷:《ECPF 多類別偵測 — 五實驗系列》。

**2b. 迴歸的 UQ 問題是靈敏度,方向是對的。** `variance_eu` 在迴歸上 +0.09 sd,雖弱但為正。這裡調門檻是有意義的(多類別則不是),也值得試更大的 `n_trees` 以降低變異數估計本身的雜訊。

**3. `ht` 在多類別上不該再當預設。** 11 個假陽性、CD 0%。`hf` 是偵測品質上的正確選擇。

**4. `similarity_margin` 迴歸版需要重新校準。** 本專案的分類路徑量的是**預測標籤**的一致率(見 §11 —— 這是相對於原論文的**修改**,不是原始定義);迴歸量的是殘差向量的 Pearson 相關對映到 (r+1)/2。0.95 在後者意味 r ≥ 0.90,而兩個對同一目標評分的專家常態相關高於此 —— 全部會被合併。目前暫定 0.80,這是待調的超參數,不是論文常數。

### 8.1 相容性

**108 次執行(多類別 54 + 迴歸 54),零 crash。** K=4 與連續目標都端到端跑完,含 ECPF 模型池。

### 8.2 這批資料的三個計分陷阱

跑之前先做了獨立稽核,結果直接改變了結果該怎麼讀。

**(a) `incremental` 的 TP/FP/CD 完全無效。** 漂移區間覆蓋率是 **1.000** —— 整條串流都在區間內:

| drift_type | 區間數 | 原始覆蓋率 | +1000 perturbation 後 |
|---|---|---|---|
| sudden | 1.7 | 0.000 | 0.034–0.044 |

**(b) `gradual` 跨 tier 的 FP 比較被覆蓋率混淆。** gradual 的覆蓋率本身隨 tier 變化(迴歸 0.488/0.289/0.164;多類別 0.858/0.590/0.281),而實測 FP 恰好反向(迴歸 0.50/1.00/1.50)。跨 tier 的 FP 差異**可被覆蓋率完全解釋**,與偵測器行為無關。

**(c) 敏感度分層只有一半可用,而且它控制的是速率不是幅度。** 生成器程式碼顯示,對 5 個 cell 而言 tier 只設定轉換寬度,概念端點的抽樣完全不看 tier。所以 `high` ≠ 漂移更大,而是**同樣的漂移被壓縮進更少樣本**。在固定觀測窗下這確實更容易偵測(偵測器不會隨生成器寬度自我縮放),因此它是**難度軸而非幅度軸**:

## 10. `synthetic_dataset_joe` 的問題清單

以下每一項都經過獨立量測,並由兩路互相獨立的驗證(其中一路刻意嘗試反駁)交叉檢查。按影響程度排序。

### 10.1 `sensitivity_validation_report.csv` 的結論不可採信

**(a) 度量只讀 `y`,從不讀 `X`。** `validate_sensitivity_monotonic.py` 的 `drift_effect_classification` 與 `drift_effect_regression` 都只存取 `df["y"]`。概念漂移的定義是 P(y|X) 改變 —— 只看 y 的邊際分布**在原理上無法量測概念漂移**,量到的是先驗偏移。

對 4 類 RBF 尤其失效:RBF 漂移移動質心,而類別標籤與權重跟著質心走,所以 y 的邊際幾乎不動而 P(y|X) 劇變。他們報告的 0.036–0.067 vs 獨立量測的條件式 total-variation 0.41–0.43 —— **差約 10 倍且方向相反**。

**(b) 每個 cell 只用 1 個檔案(`g00`)。** 把他們的統計原樣重跑到全部 10 個檔案:

| cell | g00 | 10 檔平均 | 10 檔 sd | g00 的排名 |
|---|---|---|---|---|
| binary/sudden low | 0.0906 | 0.1171 | 0.0205 | **1/10(最小)** |
| binary/sudden high | 0.1635 | 0.1240 | 0.0234 | **10/10(最大)** |
| binary/gradual low | 0.0367 | 0.0733 | 0.0279 | 1/10 |

10 檔平均是 0.1171 / 0.1156 / 0.1240 —— **不單調**。他們唯一有意義的那個 `monotonic=True` 是 g00 剛好在 low 取到最小值、在 high 取到最大值的巧合。此外,用 3 個帶雜訊的估計值做 `low < medium < high` 檢定,在**真實效應為零**時仍有約 1/6 機率通過。

**(c) 迴歸的度量另有 stale-window 缺陷且未正規化。** `roll_mean` 是**尾隨** 2000 均值而 after 窗從 `e+1` 開始,所以跳變後的 `sq_err` 約等於 (level shift)²,單位是原始 y²。報告的 0.32–34.98 跨漂移型態不可比。

### 10.2 三個 cell 的分層是 no-op

`profiles.resolve` 對 binary/multiclass 的 sudden+gradual 以及 regression/gradual **只回傳 width**;概念端點來自 `_random_chained_variant_pairs`(SEA)/ `_build_concept_chain`(RBF),兩者從不接收 tier。因此**漂移幅度依建構方式即與 tier 無關**。

- **binary/sudden、multiclass/sudden**:寬度 161 / 81 / 41 對 100k 而言全是瞬時,連「速率」差異都觀測不到 → 三個 tier 實為**重複實驗**
- **regression/gradual**:River 的 `FriedmanDrift('gsg')` 用 `bool(rc.getrandbits(1))`,是 50/50 擲硬幣而非斜坡,且三個概念是寫死的常數(`||C0−C1||=4.75`、`||C1−C2||=5.23`),tier 動不了

其餘 5 個 cell 的 tier 控制**速率**(轉換寬度),不是幅度。當難度軸用可以,當幅度軸用不行。

### 10.3 `gradual/low` 退化到無法評估

| cell | 串流落在漂移區間內的比例 | 相鄰區間重疊比例 | 區間中位間隔 |
|---|---|---|---|
| binary/gradual low | **0.959** | **74%** | **−4512** |
| binary/gradual high | 0.345 | 6.6% | +8467 |
| multiclass/gradual low | 0.858 | 71% | −3060 |

全部 10 個 `binary/gradual/low` 檔案中,**沒有任何一次漂移的兩側各有 2000 筆乾淨平台**。假陽性率、偵測延遲、漂移前基線在該 cell **均無定義**。

### 10.4 `incremental` 的標註使 TP/FP/CD 失效

區間覆蓋整條串流(multiclass 覆蓋率 1.000,每檔都有從 index 0 開始的區間)。覆蓋率為 1 時假陽性數學上不可能,`cd% = (TP−FP)/N` 退化成 `TP/N`,**每步都觸發的偵測器得 100 分**。實測 36 次執行 FP 總數為 0,對照 sudden 的 142 個 FP。

### 10.5 `multiclass/incremental/high` 破壞訊號

同概念的 15-NN 誤差 0.712,而隨機猜測為 0.658 —— **比亂猜還差**。管線實測的準確率也只比多數類基線高 0.014(見 §8.2d)。生成器在段內施加 `delta = js*(target-coeff)/seg_len`,`js=2` 的超調幅度已超出概念的可學習範圍。

### 10.6 sudden cell 的漂移位置被 tier 汙染

`_max_offset_for_width = 174 * width` 會限制段內偏移。high tier 的上限是 **7134**,低於典型 segment 長度,因此漂移中心被推向每段前緣(實測首次漂移位置上限:binary/sudden low 13903 vs high 6847)。這不改變「幅度平坦」的判斷,但任何對**位置或間隔**敏感的分析在 sudden cell 上都是 tier-confounded。

### 10.7 驗證器本身有 tier 相依的樣本選擇

`validate_sensitivity_monotonic.py` 的跳過規則(`if before_end <= before_start or after_end <= after_start: continue`)在不同 tier 丟棄不同比例的漂移:binary/gradual 丟 16/68(low)vs 5/71(high);multiclass/gradual 丟 15/73 vs 2/71。統計量因此建立在**每個 tier 不同的漂移子集**上。

### 10.8 建議(對資料集)

1. 效應量改用**條件式**度量(需讀 `X`),不要用 y 的邊際
2. 每個 cell 用全部 10 個重複並報標準誤,不要只用 `g00`
3. `gradual/low` 重生成,把區間間隔拉開到不重疊
4. `incremental` 只標註**轉折點**而非整段,否則 FP 無法定義
5. `multiclass/incremental` 的 `js=2` 調低,或改為在可學習範圍內縮放
6. 若要 sudden 有真正的難度軸,需縮放**概念差距**(SEA 的 threshold 對、RBF 的質心位移),而非只縮放轉換寬度

## 11. 文獻定位(已核對原文)

以下每一項都經過原文核對,並由第四方交叉檢查(重新抓取來源、確認引文確實出現在所述章節)。**分成三類:論文支持 / 本專案自己的貢獻 / 已被推翻。**

### 11.1 已被推翻 —— 相似度的修改是「偏離原論文」,不是「還原論文意圖」

先前的判斷是:ECPF 論文描述的是「分類結果的相似度」(預測標籤),錯誤位元組只是 MOA 的實作細節,因此改成比對預測標籤是**回歸論文原意**。

**這是錯的。**

ECPF 論文(Anderson, Koh, Dobbie, Bifet, *Expert Systems with Applications* 138:112832, 2019)的 **§3.1 才是規範性定義,而它明確是錯誤導向的** —— 該節說明相似度來自對兩個分類器「各自錯誤」的成對比較,並定義 Score 在兩者的分類**錯誤**相同時為 1。更早的 CPF 論文(AusAI 2016)§3.1 更直白,寫的是對「是否有相同的分類錯誤」做位元比較。

參考實作與論文**一致**:`ECPF.java` 只呼叫布林的 `correctlyClassifies(...)`,預測標籤在進入比較前就被丟棄,接著對兩個錯誤位元組做 XOR。**沒有論文與程式碼的落差。**

我先前判斷的來源是**摘要與導論**的鬆散措辭(「similarity of classifications」),那確實讀起來像在講預測標籤 —— 但 §3.1 才是定義,而且程式碼實作的是 §3.1。

**對論文寫作的影響:** 這個修改必須定位成**對已發表演算法的提議修改**,需要自己的論證與 ablation,不能寫成「修正實作偏差」。

**→ 消融已完成(2026-08-10,`scripts/run_similarity_ablation.py`,結果於 `outputs/similarity_ablation/`)。** 開關為 `ecpf_similarity_mode`("error_bitset" 復刻原版)。K=2 對照組兩定義**逐位相同**(等價性的實證確認);K=5 循環串流(mc5_recurring)上原版定義 **8 次合併、4 次跨概念(50%)、池從 5 崩塌到 2**、重用品質 −0.063,標籤定義 3 次合併、零跨概念;K=3 與非循環串流兩者實務無差異。偏誤顯形條件(高 K × 輪迴 × 低漂移後準確率)與 §11.1 的理論分析一致。註記:標籤定義在 mc5_sudden 也出現 1 次跨概念合併 —— 它不免疫,只是不被「都錯」灌水;prequential 差異微小,傷害集中在池結構與重用品質。

### 11.2 論文支持 —— 但支持的是「問題存在」,不是「我的解法」

**問題本身是真的,而且是已發表演算法的結構性性質。** XOR 錯誤位元組會把「兩者都錯」計為一致,無論它們預測的是哪個錯誤類別。K=2 時這與標籤一致等價(二元答錯必然預測那個唯一的另一類);K>2 時嚴格較弱。這由論文 §3.1 的定義與 `ECPF.java` 的 XOR 兩者共同確認,不是誤讀。

**要精確:「ECPF 是二元的」這句話是錯的。** 參考實作宣告 `MultiClassClassifier`,正確性用 argmax 比對計算,與類別數無關;論文自己的 LED 實驗就有 10 個類別。**準確的說法是:ECPF 可以在多類別串流上執行,但它的相似度量建立在 1 bit 的正確性訊號上,因此無法區分「錯得不一樣」。**

**ECPF 作者自己把迴歸擴展列為未來工作。** 論文 §5 結論明確指出將此框架擴展到具有循環漂移的迴歸問題會很有意義、並能適用於更多領域。這是本專案迴歸方向**最直接的動機引用**,而且來自原作者。

### 11.3 本專案自己的貢獻 —— 不可引用他人

**誤差流語意(把 `|y − ŷ|` 用在整數標籤上會把標籤當序數)在文獻中找不到對應討論。** 三份主要來源(Korycki & Krawczyk 2021;Palli et al., *Applied Sciences* 2022;Wang et al., IJCNN 2013)全文檢索後,**沒有任何一處**討論此議題。

原因本身值得寫進論文:**在標準表述中,偵測器監控的量本來就是 0/1 的誤分類指示值**(Bernoulli),標籤數值從不相減,因此序數病態根本不會出現。`|y − ŷ|` 是特定**實作選擇**的產物 —— 對整數編碼的類別標籤計算迴歸式殘差再餵給偵測器 —— 而這正是把 ECPF 從二元擴展到多類別時會製造出來的情境。

**不要引用 Korycki & Krawczyk 或 Palli et al. 來支持這一點。** 它們談的是**類別不平衡**對偵測器的影響,與 ECPF 的相似度/合併機制是不同的機制。用它們背書等於「拿一個文獻替換另一個」,審稿人翻開就會發現。

同樣被交叉檢查抓出的引用錯誤:

- **DDM-OCI 監控的是少數類別的 recall,不是每個類別的 recall。**(Wang et al., IJCNN 2013 §IV-A)先前的說法錯誤。
- **不要引用 Palli et al. 支持「二元設計的偵測器在多類別上表現不佳」** —— 該文自己的結論是 DDM(最典型的二元時代錯誤率偵測器)整體排名最佳。其效應是不平衡驅動,不是類別數驅動。可引用的是「沒有任何受測偵測器在各種漂移型態上表現一致,且多數受類別不平衡影響」。
- **引用 Korycki 的導論而非摘要。** 摘要寫「all of them assume roughly balanced classes」,但同一篇 §VI-D 就在比較「已發表的 skew-insensitive 偵測器」,所以「all」與自身矛盾;導論的措辭較保守。

### 11.4 新穎性:必須收窄(已讀完迴歸漂移的系統性文獻回顧)

已取得並全文讀完 **Lima, Neto, Silva Filho, Fagundes, "Learning Under Concept Drift for Regression—A Systematic Literature Review", IEEE Access 10:45410–45429, 2022**(41 篇主要研究,涵蓋 2010–2020/08,CC BY)。這是檢驗新穎性最權威的單一來源。三個獨立 agent(兩個不同角度的讀者 + 一個對抗檢查)一致判定:**新穎性成立,但必須收窄。**

**全文機械檢索(20 頁):** `pool` **0** 次、`repository` **0** 次、`reuse`/`re-use` **0** 次、`conceptual equivalence` **0** 次、`Anderson` / `Koh` / `Dobbie` **0** 次、`RCD` **0** 次、`retrieval` **0** 次。該回顧的 126 篇參考文獻中**沒有任何一篇**分類側的模型重用框架(CPF/ECPF、RCD、RePro 皆未被引用)。兩邊的文獻是斷開的。

#### 會直接推翻「寬版」主張的前案

**Soares & Araújo, "An on-line weighted ensemble of regressor models to handle concept drifts", *Engineering Applications of Artificial Intelligence* 37:392–406, 2015**(該回顧編號 S29)。摘要明言在可能再現的情境中**重用先前取得的資訊**,而且是**迴歸**、**2015 年**。

所以 **「首次在迴歸串流上對循環概念做模型重用」這個說法是假的**,寫出去會被抓。

但它**不是 ECPF 式的**:沒有封存庫、沒有漂移觸發的檢索、也沒有拿儲存模型的行為與現役模型比較 —— 權重來自每個模型**自己對 ground truth 的誤差**,並以折扣因子調整新舊視窗的貢獻。

#### 第二個必須防守的點

**Zhu & Dai, "EnsPKDE&IncLKDE", *Applied Intelligence* 51(2):617–645, 2021**(編號 S26)依「所有基學習器**預測值**的核密度分布」動態選擇預測器集合。這是該回顧中唯一用**輸出行為**(而非自身誤差或輸入分布)選模的迴歸方法。它擋掉「首次在迴歸上以模型行為作為選擇訊號」這種說法。

#### 已檢查並排除

**Zhao, Cai & Zhou, "Handling concept drift via model reuse", *Machine Learning* 109:533–568, 2020** —— 標題極具威脅性(有模型池、偏置正則化重用、循環漂移專節),但全文中 `regression` / `regress` 出現 **0** 次:基學習器是線性**分類器**,指標是 accuracy/precision/recall。**分類專用,不構成前案。**

#### 可辯護的定位

判準的差異才是分界線,不是「有沒有池子」:

| 方法 | 重用判準 | 訊號 | 任務 |
|---|---|---|---|
| OWE (2015) | 各模型自身誤差,折扣加權 | 誤差 | 迴歸 |
| EnsPKDE (2021) | 基學習器預測值的核密度 | 輸出分布 | 迴歸 |
| CEP (2025) | 輸入統計「基因」(前二階動差)相似度 | **P(X)** | 迴歸預測 |
| Eliades & Papadopoulos (2025) | 共形鞅交換性 + F1 門檻 | — | **分類專用** |
| **ECPF / 本專案** | **概念等價**(與現役模型在近期 buffer 上的預測一致程度) | **P(y\|X)** | 分類 → **迴歸** |

**可貼進論文的最窄主張:**

> 據我們所知,這是首次將**概念等價式模型重用家族**(RePro、CPF、ECPF)擴展到迴歸串流:既有的迴歸循環漂移方法,或是僅把過往迴歸器留在活躍集成中並依其自身預測誤差重新加權(OWE, Soares & Araújo 2015),或是依輸入分布統計量從模型池檢索(CEP, Zhan et al. 2025);本工作維護明確的迴歸器儲存庫,並在偵測到漂移後**比較儲存模型與現役模型在近期 buffer 上的預測**來決定重新啟用哪一個 —— 這正是 ECPF 作者列為未來工作的方向(Anderson et al., ESWA 138:112832, 2019, §5),而最新的循環漂移綜述(Suárez-Cetrulo et al., ESWA 213:118934, 2023;Gunasekara et al., IJCAI-24)仍將其列為迴歸上尚未填補的空白。

#### 三件絕對不能寫的話

1. ❌ **「首次在迴歸上做循環概念的模型重用」** —— OWE (2015) 推翻
2. ❌ **「首次在迴歸上以模型行為作為選擇訊號」** —— EnsPKDE (2021) 推翻
3. ❌ **把「概念等價」當成自己的想法** —— 它是 Yang, Wu & Zhu (2006);而 ECPF 的相似度量依其**論文自述**是改編自 Gomes et al. (2012)

真正的貢獻應框定為:**判準本身**(與現役模型的預測一致度,且必須為連續目標重新定義 —— 實數預測的「一致」沒有自然門檻,這個改編才是實質技術貢獻)**加上池與檢索機制,移植到迴歸**。
