## 一、前置定義與上下文

### 名詞

| 名詞 | 意思 |
|---|---|
| 警報 | 系統判定發生漂移並回報的那一步 |
| GT | 資料集附的漂移標準答案，每個漂移有一個起點 `d_s` |
| 主窗 | 每個 GT 起點後的 1000 步，`[d_s, d_s+1000]`，含端點 |
| 長窗 | 每個 GT 起點後的 `delta_max` 步：covertype 2500 步，gas 1500 步。這是登記檔給兩個資料集的 `delta_max`，也是注入漸變的過渡寬度 |
| 命中 | 一個 GT 的窗內至少有一次警報，每個 GT 最多算一次 |
| 誤報（FP） | 落在所有窗之外的警報數 |
| 碰運氣的期望命中（C） | 假設警報和漂移無關、以該次執行自己的誤報率隨機出現時，預期會落進窗內的 GT 數 |
| 超額命中（X） | 命中數減 C |
| 平均偵測延遲（MDT） | 被命中的 GT，從起點到窗內第一次警報的步數，取平均 |
| 整條串流準確率 | 每筆先預測再學習，所有可計分預測中正確的比例 |
| 可計分預測數 | 暖機之後、計入準確率的預測筆數。合併多條串流的準確率時用它加權 |
| cell | 一種注入方式（class_prior、feature_filtering、feature_permutation、label_swap）配一種漂移型態（abrupt 突變、gradual 漸變），共 8 個 |
| trial | 同一個 cell 以不同亂數產生的第幾條串流，編號 g00–g49 |
| 超出碰運氣 | 一組在一個母體上的 X 合計，95% CI 下界大於 0 |
| 可判定性 | 一個母體上至少一組超出碰運氣。兩組都沒有超出碰運氣時，P2 記「不可判定」，結論只依誤報寫 |
| 警告 | 偵測器進入「可能漂移」的狀態。兩組在警告期間都暫停訓練主模型 |
| 訓練暫停步數 | 處於警告狀態、主模型沒有學習的總步數 |
| 確認 | 警告升級成漂移，發出一次警報 |
| 逾時關閉 | 主方法的警告超過 1000 步沒有確認，關閉並丟棄緩衝 |
| 離區關閉 | HDDM-A 離開 warning 區、沒有進入 drift 區，警告關閉並丟棄緩衝 |
| 參照切換 | 主方法把凍結參照模型換成目前已適應的 leader，進行中的警告隨之關閉 |
| 串流結尾未關閉 | 串流結束時警告仍開著 |
| 論文計分 | Cerqueira et al. 報 cell 的方式：同一個 cell 所有 trial 的 TP、FP、FN 先加總，再算 precision、recall、F1。窗是 `[d_s, d_s+delta_max]`。只用來描述 |

警報、GT、命中、FP、C、X、MDT、準確率的計分函式和 DET1、DET3、DET4 相同，都在 `scripts/analyze_det3.py`。本輪的腳本 `scripts/analyze_det5.py` 換掉的是：資料集、trial 範圍、每個資料集的長窗、比較清單，另外加上可判定性規則和 `det_adwin` 的描述。

### 變因

- **自變因：** 偵測方式，有兩組。
  - **DET5-E** = preset `e10bft`。兩個 ADWIN 讀凍結參照模型的損失，另加只認「變差」的 leader 守衛；警告超過 1000 步未確認就關閉。
  - **DET5-H** = preset `det1_zone_hddm_a_lw0`。HDDM-A 的 warning 區開警告，drift 區確認，參數是 MOA 預設值。
  - 這就是 DET3 的兩組，preset 檔從 DET3 登記（`d161895`）之後沒有改過。
- **判定用的依變因：** FP 和 X 用在主判定、次要判定、H2；準確率用在 H3。
- **只描述、不判定的依變因：** 命中、MDT、kappa、警告的開啟與關閉次數、訓練暫停步數、執行時間、論文計分的 F1。
- **控制變因：**
  - 學習器設定：單棵 Hoeffding Tree、ECPF 嚴格替換、ECPF 淘汰規則、模型池上限 10、暖機 200 筆、警告期間暫停訓練、`river==0.21.2`。
  - 執行條件：同一個 commit；兩組的同一條串流在同一台機器上跑。
  - 沒有調任何參數。
- **描述用的第三組 `det_adwin`：** Cerqueira et al. 的純偵測流程，一棵從不重設的 Hoeffding Tree 搭配 ADWIN（δ = 0.01），前 25% 不餵給偵測器。它不參與任何判定。

### 判定規則（登記時固定）

- **P1 誤報：** `ΔFP = FP(E) − FP(H)`，母體內合計。95% CI 上界小於 0 記「成立」，下界大於 0 記「不成立」，其餘記「持平」，包括 CI 邊界剛好是 0。
- **P2 超額命中：** `ΔX = X(E) − X(H)`，母體內合計。CI 下界大於 0 記「成立」，上界小於 0 記「不成立」，其餘記「持平」。
- **CI：** 以串流為單位、兩組配對、有放回抽樣 10,000 次，種子 `20261012`，取第 2.5 和 97.5 百分位。母體跨資料集時，分層、各層內抽樣後合計。各組自己的 X 的 CI，用同一批抽樣算。
- **結論：** 兩項都成立是「優於」，兩項都不成立是「不如」，一項成立、一項不成立是「有得有失」，任一項持平就是「持平」。
- **可判定性：** 兩組在一個母體上都沒有超出碰運氣時，P2 記「不可判定」，結論改寫成「兩組的偵測都接近碰運氣；誤報 E 較少／較多／持平」。
- **主判定：** 兩個資料集各一個，各 320 條，用主窗。
  - 兩個結論相同時，才寫成一句總結。
  - 不同時分開寫，並和 DET3 在 electricity 上的結論並列。
  - 如果只有 gas 判「優於」，必須註明 gas 是主方法發展期間用過的來源。
- **三個次要判定：** 同一套 P1、P2。
  1. covertype 用長窗（2500 步）。
  2. gas 用長窗（1500 步）。
  3. 兩個資料集合計 640 條，用主窗。
  - 次要判定不改變主判定。主判定不是「優於」而長窗是「優於」時，兩個要一起寫。
- **H2 漸變與突變：** 每個資料集的 gradual 和 abrupt 各 160 條，分開算 `ΔX`，主窗和長窗各算一次。CI 下界大於 0 記「主方法較多」，上界小於 0 記「主方法較少」，其餘記「沒有差別」。
- **H3 準確率：** `Δacc` 是兩組整條串流準確率的差，以可計分預測數加權，每次抽樣重算。CI 全正記「較好」，全負記「較差」，其餘記「持平」。在兩個主判定和三個次要判定的母體上各算一次。

## 二、背景與動機

**問題。** DET3（單棵樹）判定 E10bFT 的偵測不優於 HDDM-A，結論是持平。DET4（10 棵樹的森林）判定是不如。兩輪的主判定都只用注入漂移的 electricity，而 electricity 是整個專案用得最多的資料集。主方法的劣勢可能是 electricity 特有的，也可能在別的資料上一樣，沒有證據可以分辨。

**為什麼要另開一輪。** 登記檔裡還有兩個用同一套注入程式產生、但來源不同的資料集：covertype 和 gas。兩組都沒有在這兩個資料集的 `injected_paper` 版本上跑過，所以先登記規則再跑，用來回答「DET3 的結論換了來源資料集還成不成立」。

**登記時已經知道的事：**

- DET1 到 DET4 的全部結果。
- 這兩個來源資料集在 E 系列用 main 上的舊版注入檔用過：
  - gas 的 10 個 trial，在 A2 到 E12 全部用過；
  - covertype 在 E13 用過 2 個 trial（森林），三組的超額命中都在 −0.2 到 2.7 之間，E14 因此排除了 covertype。
- 隊友在原始順序的全長 covertype 上跑過標準組：e10bft 警報 3,848 次。
- 論文在 covertype 上，除了 feature_permutation 以外，最好的 F1 只有 0.065–0.189。
- 試跑：只讀了 g49 的執行時間。

**登記時不知道的事：** 兩組和 `det_adwin` 在 g00–g48 任何一條上的結果；HDDM-A 在這兩個來源資料集任何版本上的結果。

**事前預測（登記時寫下）：**

- **covertype：** P2 不可判定，兩組都接近碰運氣。P1 不成立，E 的誤報較多。結論會寫成「兩組的偵測都接近碰運氣、誤報 E 較多」。
- **gas：** 持平。
- **H3：** 兩個資料集都持平。
- **H2：** 不預測方向。

### 4.4 假說驗證

**H2 漸變與突變（各 160 條）：**

### 4.7 事後觀察（登記後才想到，不是判準）

- **四個母體的 ΔX 都是負的，而且 CI 都在 0 以下。** 在 1000 步主窗下，主方法的超額命中在 DET3、DET4、DET5 的四個主判定母體上都明確較少。不論資料集、學習器，這是 DET 系列最一致的結果。
- **誤報方向依資料集而定。** electricity 上主方法的誤報較多；covertype 上明顯較少；gas 上差不多。covertype 是 HDDM-A 特別吵的資料：它開了 13,695 次警告，其中 12,320 次離區關閉，FP 1,155。主方法在 covertype 的 8 個 cell 中，FP 每一個都比較少。
- **主方法是慢，不是完全抓不到。** MDT 在兩個資料集都比較長（414 對 342、577 對 357 步）。covertype 放到 2500 步長窗後，主方法的 X 追上了 HDDM-A（84.08 對 81.25）；gas 放到 1500 步長窗後仍較少（114.67 對 128.96）。
- **covertype 的超額命中主要來自 feature_permutation。** 主方法 63.20 中有 45.3，HDDM-A 78.89 中有 64.4。其餘三種注入方式，兩組各自的 X 合計都在 0.7 到 11.5 之間（每種 80 條），接近碰運氣。所以登記時「covertype 很難偵測」的判斷，對其中三種注入方式大致成立，只是 feature_permutation 讓兩組都超出碰運氣。
- **gas 上主方法的落後集中在 feature_filtering 和 label_swap。** X 分別是 6.6 對 13.3、6.2 對 14.6。
- **訓練暫停的差距比 electricity 小很多。** 主方法對 HDDM-A 的暫停步數比，在 electricity 約 8 到 10 倍，在 covertype 約 1.7 倍，在 gas 約 1.3 倍。HDDM-A 在這兩個資料集開了很多短警告。

## 五、局限性與衍生問題

**局限：**

- **範圍窄：** 只有單棵 Hoeffding Tree、一個亂數種子、兩個來源資料集、一套注入程式（Cerqueira et al. 的四種方式、兩種型態）。結論不能推到森林、迴歸或沒有注入的真實漂移。
- **gas 用過：** gas 是主方法發展期間用過的來源資料集。本輪用的是新串流，而且 gas 沒有判「優於」，所以這個問題不影響結論的方向；但如果有人拿 gas 的結果去支持主方法，要記得這一點。
- **gas 很短：** gas 每條只有 13,910 筆，扣掉前 25% 不計分，可計分的部分大約一萬步，誤報的機會比 electricity 和 covertype 少很多（兩組 FP 合計 144、122）。
- **covertype 的證據集中在一種注入方式：** covertype 的偵測證據大多來自 feature_permutation 這一種方式。另外三種方式兩組都接近碰運氣，在那三種方式上，本輪沒有比較偵測能力的力量。
- **準確率偏低：** 兩個資料集的準確率都在 0.55 上下。兩組都是單棵樹，加上打亂和注入，準確率本來就不高。這次比較的是偵測，不是學習器的好壞。
- **長窗不一致：** 兩個資料集的長窗長度不同，各取 `delta_max`。
- **沒調參：** HDDM-A 用 MOA 預設參數，主方法的參數是在別的資料上定的，兩邊都沒有在這批串流上調參。
- **先看過結果：** 本輪是看過 DET3、DET4 之後才決定跑的。新的串流和不變的規則降低了這件事的影響，但無法完全排除。

**衍生問題：**

- 主方法在 covertype 上誤報少很多。這是 DET 系列第一次看到 P1 成立。原因看起來是 HDDM-A 在 covertype 上過度敏感，而不是主方法在 covertype 上特別好；但本輪沒有能區分這兩種解釋的設計。
- 主方法偵測較慢，這在四個母體上都出現。主方法的四個元件（凍結參照、leader 守衛、逾時、兩個 ADWIN）中，是哪一個造成延遲，DET 系列都沒有拆開過。

**下一步（都還沒做）：**

1. **論文的偵測主張：** 在 electricity、covertype、gas 三個來源資料集，單棵樹和森林兩種學習器上，都不能主張 E10bFT 的偵測優於 HDDM-A。比較可靠的寫法是：
   - 主方法確認較慢，1000 步窗內的超額命中較少；
   - 誤報的高低依資料集而定，在 HDDM-A 很吵的資料上（covertype）主方法的誤報明顯較少。
2. **長窗的主張要另外登記：** 如果要主張「放寬計分窗後主方法不輸」，需要另外登記一輪，用沒用過的串流。可用的有 electricity 的 g40–g49，以及這兩個資料集的 g40–g48。本輪 covertype 的長窗結果是持平，沒有支持「優於」。
3. **拆開延遲的來源：** 要知道延遲來自哪個元件，可以在同一批串流上逐一拿掉主方法的元件。這是新設計，要先登記。
4. **校準 `det_adwin`：** 如果要拿它校準，需要取得論文中 ADWIN 自己在這兩個資料集的數字（論文的 hypertuned results.csv），登記檔目前沒有。

## 偏離與補充

- **沒有偏離。** 機器（node2）、計分地點（node2）、trial 範圍、組別、閘門順序，都和登記相同。沒有缺漏的串流，沒有重試，每條串流每組只跑一次。判定規則沒有更動，所以預註冊沒有追加修訂。
- **執行時間超出預估**（3.1 小時對 4 小時 25 分），見 4.7。時間不是登記的條件。
- **計分完成後**，判定資料和逐條分數從 node2 複製回本機，雜湊相同。
- **每條串流的 `y_true` 雜湊** 在逐條分數檔裡。
- **記憶體峰值** 在 Windows 上量不到，記為 0，沒有列入。
