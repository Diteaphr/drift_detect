## 一、前置定義與上下文

### 名詞

| 名詞 | 意思 |
|---|---|
| 警報 | 系統判定發生漂移並回報的那一步 |
| GT | 串流附的漂移標準答案。注入串流每條 1 個漂移，起點 `d_s` |
| 短窗 | `[d_s, d_s + 1000]`，含端點。主判定和大部分次要判定用它，和 DET3 到 DET5 的主窗相同 |
| 長窗 | `[d_s, d_s + delta_max]`，delta_max 取登記檔的值：electricity 2500、covertype 2500、gas 1500 |
| 命中 | 一個 GT 的窗內至少有一次警報，每個 GT 最多算一次 |
| 誤報（FP） | 落在窗外、而且在計分範圍內的警報數 |
| 碰運氣的期望命中（C） | 假設警報和漂移無關、以該次執行自己的誤報率隨機出現時，預期會落進窗內的 GT 數 |
| 超額命中（X） | 命中數減 C |
| 平均偵測延遲（MDT） | 被命中的 GT，從 `d_s` 到窗內第一次警報的步數，取平均 |
| 整條串流準確率 | 每筆先預測再學習，所有可計分預測中正確的比例，以可計分預測數加權合併 |
| trial | 同一個 cell 以不同亂數產生的第幾條串流，編號 gNN |
| 超出碰運氣 | 一組在一個母體上的 X 合計，95% CI 下界大於 0 |
| 可判定性 | 一個母體上至少一組超出碰運氣。兩組都沒有超出時，P2 記「不可判定」，結論只依誤報寫 |
| 凍結參照 | 每次確認漂移時凍結一份模型，500 步後再從已適應的 leader 重新凍結一次。偵測器讀的是這份凍結模型的 0/1 損失，不是 leader 的 |
| leader 守衛 | 另一組只認「變差」的雙 ADWIN，讀 leader 自己的 0/1 損失。它和讀凍結參照的偵測器，任一個開警告或確認都算 |
| 警告、確認、逾時關閉、離區關閉、參照切換、串流結尾未關閉 | 和 [DET5 判定](ECPF_DET5_判定.md)第一節相同。本輪 G3、G 也用 HDDM-A 的 warning 區，所以也有離區關閉 |
| 訓練暫停步數 | 處於警告狀態、主模型沒有學習的總步數。四組在警告期間都暫停訓練 |

警報、GT、命中、FP、C、X、MDT、準確率的計分函式和 DET1、DET3 到 DET6 相同，都在 `scripts/analyze_det3.py`。本輪的 `scripts/analyze_det7.py` 直接呼叫它們，可判定性照 `scripts/analyze_det5.py` 的寫法，只是把比較的兩組改成參數。

### 變因

- **自變因：** 偵測方式。四組都用單棵 Hoeffding Tree。
  - **G3（受測）** = preset `det7_g3`。HDDM-A（drift 信賴度 3e-4、warning 信賴度 1.5e-3）讀凍結參照的損失；另加 leader 守衛；警告超過 1000 步沒有確認就關閉。
  - **H（對照）** = `det1_zone_hddm_a_lw0`。HDDM-A（預設 drift 0.001、warning 0.005）讀 leader 的損失。
  - **G（次要）** = `det7_g`。同 G3，但 HDDM-A 用預設參數。
  - **E（次要）** = `e10bft`，現行主方法。兩個 ADWIN 讀凍結參照的損失，另加 leader 守衛和 1000 步逾時。
  - G3、G 的 config 就是 E10bFT 的 config，再加 `ecpf_zone_detector: hddm_a`；G3 另設 `ecpf_zone_drift_confidence: 0.0003`。E、H 的 preset 從 DET3 登記（`d161895`）以後沒改過。
- **判定用的依變因：** FP 和 X 用在主判定、次要判定、H2；準確率用在 H3。
- **只描述的依變因：** 命中、MDT、kappa、警告的開啟與關閉次數、訓練暫停步數、執行時間。
- **控制變因：** ECPF 嚴格替換、ECPF 淘汰規則、模型池上限 10、暖機 200 筆、警告期間暫停訓練、`river==0.21.2`、同一個 commit、同一台機器。沒有在判定資料上調任何參數。

### 判定規則（登記時固定）

- **P1 誤報：** `ΔFP = FP(受測) − FP(對照)`，母體內合計。95% CI 上界小於 0 記「成立」，下界大於 0 記「不成立」，其餘記「持平」。
- **P2 超額命中：** `ΔX = X(受測) − X(對照)`，母體內合計。CI 下界大於 0 記「成立」，上界小於 0 記「不成立」，其餘記「持平」。
- **CI：** 以串流為單位、兩組配對、有放回抽樣 10,000 次，種子 `20261012`，取第 2.5 和 97.5 百分位。單一資料集不分層，合併時依資料集分層。各組自己的 X 的 CI 用同一批抽樣算。
- **結論：** 兩項都成立是「優於」，兩項都不成立是「不如」，一項成立、一項不成立是「有得有失」，任一項持平就是「持平」。
- **可判定性：** 兩組都沒有超出碰運氣時，P2 記「不可判定」。
- **主判定：** electricity，640 條，短窗，G3 對 H。範圍限於「注入漂移的真實資料串流、單棵 Hoeffding Tree、警告期間暫停訓練」，並要註明 3e-4 是在開發資料上選的。主判定若是「優於」而 covertype 或 gas 不是，要一起寫。
- **六個次要判定：** 同一套規則，各自判定，不改變主判定。1 covertype、2 gas（都是短窗，G3 對 H）；3 三個資料集的長窗；4 預設參數 G 對 H；5 G3 對 E；6 三資料集合併。
- **H2：** 每個資料集分突變、漸變兩半，短窗和長窗各算 G3 對 H 的 `ΔX`。CI 下界大於 0 記「G3 較多」，上界小於 0 記「G3 較少」，其餘記「沒有差別」。
- **H3：** `Δacc` 是兩組整條串流準確率的差，每次抽樣重算。CI 全正記「較好」，全負記「較差」，其餘記「持平」。

## 二、背景與動機

**問題。** DET3 到 DET5 的四個主判定，在 1000 步窗內，E10bFT 的超額命中都比 HDDM-A 少，ΔX 的 CI 都整段在 0 以下。DET6 在合成慢速漸變上判「優於」，但換成森林就「不如」。主方法在一般速度的漂移上一直沒有贏過 HDDM-A。

**為什麼要另開一輪。** 2026-10-19 的兩次開發檢查找到了原因：
- **B2 重播：** 在 DET3 的 160 條上，延遲幾乎都在開警告之前。同一條訊號換 HDDM-A 讀，就追上 H。在相同誤報下，HDDM-A 讀凍結參照比讀 leader 多抓約 7 個漂移。也就是說，凍結參照的訊號不差，慢的是讀它的雙 ADWIN。
- **B3-dev：** 用真實 pipeline 在 DET3 的 205 條上跑。G3 在 injected 160 條上對 H 是 ΔFP −24 [−45, −3]、ΔX +5.69 [−3.42, +14.78]，對 E 是「優於」；但在多漂移的合成資料上，X 比 H 低。

兩次檢查用的都是已判定過的資料，3e-4 也是在同一批資料上挑的，所以不能當證據。本輪用新的 trial 和事先定好的規則，回答「G3 的偵測有沒有比 HDDM-A 好，在 covertype、gas 上是否成立，代價是什麼」。

**登記時已經知道的事：** DET1 到 DET6 的全部結果；B2、B3-dev 的結果；g199 試跑的執行時間。

**登記時不知道的事：** 任何一組在判定用 trial 上的結果；G3、G 在 covertype、gas 上的表現。

**事前預測（登記時寫下）：**

- **主判定：** P1 成立、P2 持平，結論「持平」。
- **covertype：** P1 成立、P2 持平，結論「持平」。**gas：** P1、P2 都持平，結論「持平」。
- **長窗：** electricity「優於」，covertype、gas「持平」。
- **G 對 H：** P1 持平、P2 成立，結論「持平」。**G3 對 E：** 「優於」。**合併：** P1 成立、P2 持平，結論「持平」。
- **H2：** electricity 突變「G3 較多」，其餘「沒有差別」。**H3：** 全部持平。

**登記的程序。** 使用者 2026-10-20 要求「用 G3 為主、在新資料上寫 DET7 預註冊後在本機開跑」。組別、資料和計分窗由登記人提出，預註冊在登記前沒有經過使用者逐條審閱，這一點在預註冊第二節已經寫明。

### 4.8 事後觀察（登記後才想到，不是判準）

- **covertype 的差距集中在 feature_permutation。** 這個注入方式下，G3 命中 29 個、H 67 個（各 80 條）；其他三種方式兩組都接近碰運氣，或 G3 不輸。feature_permutation 是把特徵欄位打亂，錯誤率上升得不一定明顯，而 HDDM-A 在 covertype 上本來就很敏感（13,723 次警告開啟）。這個解釋沒有驗證過。
- **electricity 上的增減和 B2 預期的不同。** B2 裡，凍結參照和 leader 在漂移時的錯誤率跳升，差距最大的是 label_swap 突變（中位數 0.211 對 0.025），照理 G3 在 label_swap 上最占優勢。本輪 G3 在 label_swap 反而比 H 少（85 對 101），優勢在 class_prior（18 對 4）和 feature_permutation（91 對 78）。開發資料上的這個解釋沒有在新資料上得到支持。
- **G3 仍然比 H 晚。** 三個資料集的 MDT 都是 G3 較長（426 對 341、407 對 317、401 對 381）。3e-4 比 H 的 0.001 保守，用較少的誤報換來較晚的偵測。electricity 長窗下 G3「優於」，漸變一半的 ΔX 從短窗的 −3.00 變成長窗的 +32.94，也顯示 G3 多出來的命中多半落在 1000 步之後。
- **3e-4 的效果轉移到了新資料。** 預設參數的 G 超額命中和 G3 相當，誤報卻比 G3 多 53%、比 H 多 78 個。所以 G3 的誤報優勢來自工作點，不只是因為改讀凍結參照。
- **準確率較差和訓練暫停無關。** DET6 曾猜主方法準確率較差和訓練暫停較多有關。本輪 G3 的訓練暫停在三個資料集都比 H 少，準確率在 electricity、covertype 仍然略差。原因沒有拆開驗證。

## 五、局限性與衍生問題

**局限：**

- **工作點是在開發資料上選的：** 3e-4 和保留守衛，都是看過 DET3 的 g00–g19 後決定的。本輪用新的 trial 降低偏誤，次要判定 4 顯示預設參數會讓誤報變多，所以結論依賴這個工作點。
- **沒有測多漂移的合成資料：** B3-dev 在 Joe 的 synthetic_multiclass 上，G3 的 X 比 H 低。這份資料沒有新的串流可用，產生器也不在 repo 裡。本輪的結論不涵蓋一條串流裡有多個漂移、而且概念會重複出現的情況。
- **只有單棵樹：** 森林沒有測。DET4、DET6 的森林結果和單棵樹方向不同。
- **covertype 的取捨：** 誤報少很多，但抓得較少、準確率較差。不能把三份資料合起來寫成「G3 比 HDDM-A 好」。
- **準確率略差：** electricity 差 0.07 個百分點、covertype 差 0.25 個百分點，都是 CI 全負。
- **檢定力不足：** 主判定的 ΔX CI 跨 0，可能只是條數不夠，也可能真的沒有差別。本輪的資料分不出這兩種情況。
- **登記前沒有經過使用者審閱：** 預註冊由登記人依建議寫成後直接提交執行。
- **計分不是 harness 協定：** 和 DET3 到 DET6 相同，用 DET1 的窗規則和超額命中。

**衍生問題：**

- covertype 的 feature_permutation 上，G3 為什麼少抓那麼多？是凍結參照在這種注入下訊號不明顯，還是 3e-4 太保守？
- 有沒有一個工作點，能在 covertype 上不輸、同時保留 electricity 和 gas 的誤報優勢？這必須在開發資料上找，再用新的 trial 登記。
- G3 在多漂移合成資料和森林上會怎樣？
