# DET3 預註冊：主方法 E10bFT 對 HDDM-A

**登記：** 2026-10-13（Asia/Taipei），以本文件的 commit 為準。主方法在判定資料上的任何執行，都在本文件與計分腳本提交之後才開始。本文件提交後不改寫，偏離一律追加在末尾「修訂」。

**頂層問題：** DET1 顯示，把 ECPF 的偵測器換成現成的 HDDM-A，誤報就比原本的雙 ADWIN 少，命中也比較多。主方法 E10bFT 用四個自訂元件處理同一個問題，但 DET1、DET2 都沒有把它納入正式比較。本輪要回答：在同一個 ECPF 底座、同一批資料、同一套計分下，E10bFT 的偵測有沒有比 HDDM-A 好。

背景來源：[DET1 預註冊](ECPF_DET1_預註冊.md)、[DET1 verdict](../outputs/det1/det1_verdict.md)、[DET2 預註冊](ECPF_DET2_預註冊.md)。

## 一、名詞

| 名詞 | 意思 |
|---|---|
| 警報 | 系統判定發生漂移並回報的那一步 |
| GT | 資料集附的漂移標準答案，每個漂移有一個起點 `d_s` |
| 主窗 | 每個 GT 起點後的 1000 步，`[d_s, d_s+1000]`，含端點，超出串流結尾的部分截掉 |
| 命中 | 一個 GT 的主窗內至少有一次警報。每個 GT 最多算一次 |
| 誤報（FP） | 落在所有主窗之外的警報數 |
| 碰運氣的期望命中（C） | 假設警報和漂移無關、以該次執行自己的誤報率隨機出現時，預期會落進主窗的 GT 數。`λ = FP / O`，`O` 是可計分步數扣掉所有主窗，`C = Σ(1 − exp(−λ·|W_i|))` |
| 超額命中（X） | 命中數減 C |
| 平均偵測延遲（MDT） | 被命中的 GT，從起點到主窗內第一次警報的步數，取平均 |
| 整條串流準確率 | 每筆先預測再學習，所有可計分預測中正確的比例 |

以上定義和 DET1 完全相同，計分沿用 DET1 的函式。injected 的警報、GT 和串流長度用原始輸入座標，前 25% 的警報不計分；其餘資料暖機 200 筆之前的 GT 不計分。

## 二、兩個組別

| 代號 | preset | 偵測方式 |
|---|---|---|
| DET3-E | `e10bft`，main 的既有檔案，不修改 | 兩個 ADWIN 讀凍結參照模型的損失，另加只認「變差」的 leader 守衛；警告超過 1000 步未確認就關閉 |
| DET3-H | `det1_zone_hddm_a_lw0`，DET1 的 A3，不修改 | HDDM-A（MOA 預設參數）的 warning 區開警告、drift 區確認 |

**兩組共同的部分：** 單棵 Hoeffding Tree、ECPF 嚴格替換、ECPF 淘汰規則、模型池上限 10、暖機 200 筆、警告期間暫停訓練、`river==0.21.2`。`e10bft` 沒有寫明替換、淘汰和模型池這四個欄位，登記前已核對 `PipelineConfig` 的預設值和 `ecpf_paper` 明寫的值相同。所以兩組的差異只在偵測相關欄位。

不調任何參數。兩個 preset 檔在本輪不得編輯。

## 五、判定規則

### 主判定：只看 injected 層（160 條）

選 injected 當主判定，是因為只有這一層對兩個方法都是沒看過的串流。

| 條件 | 量 | 成立 | 不成立 | 持平 |
|---|---|---|---|---|
| P1 誤報 | `ΔFP = FP(E) − FP(H)`，160 條合計 | 95% CI 上界小於 0 | 下界大於 0 | 其餘，含碰到 0 |
| P2 超額命中 | `ΔX = X(E) − X(H)`，160 條合計 | 95% CI 下界大於 0 | 上界小於 0 | 其餘，含碰到 0 |

**CI 的算法：** 以串流為單位、兩組配對、有放回抽樣 10,000 次，種子 `20261012`，取第 2.5 和 97.5 百分位。每次抽樣重新合計 ΔFP 和 ΔX。這和 DET1 相同。

| P1 | P2 | 結論 | 對主方法主張的意義 |
|---|---|---|---|
| 成立 | 成立 | E10bFT 優於 HDDM-A | 可以主張偵測設計比 HDDM-A 好，範圍限於本節末的條件 |
| 不成立 | 不成立 | E10bFT 不如 HDDM-A | 不能再以偵測品質作為相對於文獻偵測器的主張 |
| 一個成立、一個不成立 | | 有得有失 | 照實寫哪一項較好、哪一項較差，不下勝負結論 |
| 任一持平 | | 持平 | 不能主張優於 HDDM-A。論文必須把 HDDM-A 寫成效果相當、而且比較簡單的做法 |

結論一律加上條件：「單棵 Hoeffding Tree、警告期間暫停訓練、注入漂移的 electricity、1000 步主窗」。

### 次要判定：同一套 P1、P2，換母體

以下三個各自判定、各自標示「次要」，不改變主判定：

1. **synthetic 層（40 條）。** 主方法的設計接觸過這批資料，結果只能寫成「在設計時用過的資料上」。
2. **injected 加 synthetic（200 條）。** 分兩層、各層內抽樣後合計，做法同 DET1。
3. **DET1 的完整母體（加上有 GT 的 4 條 INSECTS，共 204 條）。** 只為了和 DET1 的表格並排。

主判定和次要判定方向相反時，兩邊都保留、都寫出來。

### 次要假說

- **H2 漸變漂移。** 依據是 E9 看到 HDDM-A 在漸變漂移上命中很少。母體是 injected 的 4 個 gradual cell，共 80 條。`ΔX` 的 CI 下界大於 0 記為「支持」，上界小於 0 記為「相反」，其餘記為「沒有差別」。abrupt 的 80 條用同一規則並列。
- **H3 準確率。** `Δacc` 是兩組整條串流準確率的差，以可計分預測數加權，每次抽樣重算。CI 全正記為「較好」，全負記為「較差」，其餘「持平」。在主判定和三個次要判定的母體上各算一次。若 P1、P2 判優於而準確率 CI 全負，結論必須寫成「偵測較好、準確率較差」；反過來也一樣。

## 六、敏感度分析（不改變判定，結果不同時必須並列）

- **S1 排除可能被試跑看過的串流。** 去掉 injected 的 g00–g02（24 條），用剩下的 136 條重算主判定。
- **S2 較長的計分窗。** injected 的漸變注入寬度是 2500 步，1000 步主窗可能在漂移完成前就結束。把窗改成登記檔的 `delta_max = 2500`，其餘不變，在 injected 160 條上重算 P1、P2、H2。
- **S3 對其他組別。** DET3-E 對 DET1 的 A1（雙 ADWIN）和 A4（RDDM），用主判定的規則和 DET1 的存檔分數，各算一次。

## 七、事前預測

- **不預設主判定的方向。** INSECTS 上兩組幾乎相同；主方法在舊版注入 electricity 上（E14）誤報少、超額命中多，但那是對原本的雙 ADWIN，不是對 HDDM-A。
- **主方法的風險在延遲。** E14 記錄主方法在 electricity 上從漂移到確認的中位數約 1200 步，超過 1000 步主窗。如果這次也是這樣，會有警報落在窗外被算成誤報，P1、P2 都受影響。S2 用來看這件事。
- **H2 預測支持。** 凍結參照在 E9 的漸變漂移上命中比 HDDM-A 多。DET1 存檔裡 HDDM-A 在 injected 漸變的 80 個漂移只命中 10 個，空間很大，但也可能是 1000 步窗太短，兩組都抓不到。
- **H3 預測持平。**

## 八、閘門

任何一項沒過就停下來回報，不往下跑。

1. **G1 環境。** 在本輪的 commit 上跑 electricity 的 `e10bft`，37 個欄位要和 main 提交的結果完全相同。
2. **G2 重現 HDDM-A。** 在本機、本輪的 commit 上把 DET3-H 的 205 條全部重跑。每一條的警報數、TP、FP、FN、命中數、可計分筆數、`y_true` 雜湊要和 DET1 存檔的 A3 完全相同，C、X、準確率、kappa 的差小於 1e-9。
   - 全部相同：判定用本機重跑的 DET3-H，兩組同機器、同 commit。
   - 有不相同：列出每一條的差異，判定仍用本機重跑的 DET3-H，並在 verdict 寫明和 DET1 存檔不一致。這種情況下 S3 改標「參考」。
3. **G3 計分。** 本輪計分腳本對 DET3-H 算出的分數就是 G2 用來比對的分數。G2 全部相同，等於確認本輪計分和 DET1 一致。
4. **G4 配對。** 兩組的串流集合要相同，每條的 `y_true` 雜湊要相同。
5. **G5 完整性。** 每組 205 個結果、沒有錯誤列、commit 固定、工作目錄乾淨、不是試跑、有記錄警告事件，而且警告的開啟數等於關閉數加串流結尾未關閉數。

## 九、執行

- **順序固定：** 提交本文件，提交計分腳本，G1，重跑 DET3-H（G2、G3），最後才跑 DET3-E。DET3-E 在判定資料上只跑一次。
- **失敗處理：** 個別執行失敗用 `--resume` 重試一次。仍失敗的串流列為缺漏，含缺漏的判定標「不可判定」，不刪掉、不用別的資料替代。
- **指令：** `scripts/run_benchmark.py --resume --record-warning-events`，injected 加 `--trials 20`，輸出只放 `outputs/benchmark/det3/`。
- **本機是 Windows。** 執行工具有三處在 Windows 不能跑，修正在本分支單獨提交，寫成只在 Windows 生效，Mac 和 Linux 的行為不變。執行時設 `PYTHONUTF8=1`。記憶體峰值在 Windows 量不到，記為 0，不參與任何判定。

## 十一、限制

- 只有一種學習器、一種來源資料集的注入漂移。結論不能推到森林、迴歸或其他真實資料。
- synthetic 不是新資料，INSECTS 的結果已經看過，所以主判定只用 injected。
- injected 每個 cell 只有 20 個 trial，每條只有一個漂移。
- HDDM-A 用 MOA 預設參數，沒有調過；主方法的參數是在別的資料上定的。兩邊都沒有在這批 injected 串流上調參。
- 1000 步主窗是 DET1 和登記檔的設定，不是主方法原本實驗用的 3000 步。
