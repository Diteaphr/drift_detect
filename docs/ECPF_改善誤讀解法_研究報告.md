## 一、前置定義與上下文

### 1.1 核心概念

**ECPF 生命週期。** ECPF（Enhanced Concept Profiling Framework；Anderson、Koh、Dobbie、Bifet 2019）是一個「模型池＋重用」的串流學習框架。我們的實作（Python／river）中，一次適應的流程如下：

1. 偵測器發出 **warning**，開始把資料存進 **warning 緩衝**；warning 開啟期間 leader 與 shadow 都**不訓練**（`pipeline.py` 提前返回）。
2. 偵測器發出 **drift**，形成一次**確認**（confirmation）。
3. 框架把當前 leader 凍結進模型池，挑出在緩衝上分數最高的池內模型，把它的複本**安裝**為新 leader。
4. 同時用緩衝訓練一個新的 **shadow** 模型。之後每一步進行**對決**：shadow 自上次漂移以來的累計正確數只要嚴格多於 leader，就**換將**（兩者對調），沒有最少樣本數，也沒有門檻。

**雙臂 ADWIN（dual ADWIN）。** 目前主線的偵測器是兩個 river ADWIN，讀同一條訊號：
- **warning 臂：** δ_w = 0.1。
- **drift 臂：** δ_d = 0.05。

這兩個值其實是 ECPF 論文給 MagSeed 偵測器的參數，不是 ADWIN 慣用的值（慣用值約 0.002）。其他設定與重建規則：
- 兩臂的 `grace_period` 為 30，`clock` 為 32（只在每 32 步評估一次切點）。
- drift 臂每觸發一次，`update_values` 就把兩臂一起重建。
- warning 臂觸發後，river 會在下一次更新時自行清空該臂。

**改善誤讀（improvement read as drift）。** river 的 ADWIN 是**雙向**的：誤差顯著下降時，它觸發得和上升一樣快。自適應學習器的誤差在概念內本來就會下降，因此產生三類誤報：

| 類別 | 機制 |
|---|---|
| **餘波**（echo） | 對決換將後誤差驟降，ADWIN 把這個下降當成變化 |
| **孤兒**（orphan） | 適應後學習曲線的慢速下降，最後被 ADWIN 的長視窗切開 |
| **重用連鎖反應**（cascade） | warning 緩衝常只有 1 筆，挑錯模型安裝，誤差跳升，再次觸發 |

**原生切點方向（native cut direction）。** ADWIN 切窗時會丟掉舊子窗、保留新子窗。本報告採用 MOA `ADWINChangeDetector` 的語意：切窗後的估計值（新子窗平均）**高於**切窗前的估計值，稱為**上升切點**；否則稱為**下降切點**，相等也歸為下降。

**原生方向閘（E1）。** 只回報上升切點。下降切點照樣切窗，但不回報，而且**保留切窗後的視窗**，這一點與 MOA 相同。實作為 `_OneSidedADWIN`，旗標 `ecpf_adwin_one_sided`。

**凍結參照（frozen reference，E2）。** 偵測器不再讀 leader 的損失，改讀一個**凍結模型**的損失：
- **k = 0：** 確認時把剛安裝的 clone 凍結，一直用到下一次確認。
- **k = 500：** 確認後先用 clone，500 步後改用「已適應 500 步的 leader」重新凍結。重新凍結的那一步稱為**切換**：兩臂重建、關閉開啟中的 warning、清空緩衝。

凍結模型不會學習，所以它的損失只會因資料改變而改變（P(X)、P(y|X) 或雜訊），換將和學習曲線都不會進入偵測器的輸入。
- 迴歸：參照用自己的正規化器，每次凍結時重設。
- 分類（本輪新擴充）：參照讀 0/1 損失。

**正規化器與追趕（catch-up）。** 迴歸的誤差訊號是線上正規化後的絕對殘差。`ErrorNormalizer` 用自上次重設以來的累計均值與標準差（Welford）把殘差映到 [0, 1]。學習器變好之後，累計統計量會慢慢追上新的低水準，於是**原始殘差不變、正規化值卻上升**，稱為**追趕**。**P3** 是既有處方：每次確認時重設這個正規化器，迴歸各輪的基線都開著它。

**離線重播（offline replay）。** 基線路徑中，任何切點都會觸發並重建視窗，所以每一臂的視窗恰好等於「上次重建以來的全部輸入」。tracer 已逐步記錄偵測器的輸入與兩臂的觸發旗標，因此用同參數的 river ADWIN 重播這些輸入，就能精確重現每一次觸發，並在觸發當下讀出切窗前後的估計值與寬度。E0 與 E6 的前置量測都用這個方法，不必修改 `src/`。

**預註冊（pre-registration）與保留資料（held-out）。** 每一輪都先把臂、判準與結論規則寫成文件，機械化判定，不在看過結果後調整門檻。E8 只在前面各輪從未用過的串流上判定，因為它要檢驗的切法本身是看過 E7 結果才提出的。

## 二、背景與動機

### 2.1 現狀與痛點

多類別與迴歸兩個診斷系列（`docs/ECPF_多類別偵測_五實驗系列.md`、`docs/ECPF_迴歸側FP診斷_研究報告.md`）已確立三件事：
- 召回已達 90–100%，瓶頸是 FP。
- FP 的主體是改善誤讀，也就是餘波與孤兒；迴歸另有連鎖反應與正規化器非平穩。
- ADWIN 是雙向的，這一點已直接量測確認。

本輪之前試過的處方：

| 處方 | 結果 |
|---|---|
| 確認時重置 ADWIN | 完全無效：餘波發生在確認後數百步的換將 |
| 確認後冷卻期 | 有效，但代價與漂移密度成正比 |
| 方向閘 v1／v2／v3（純量、自訂基準） | 三版預註冊全敗、關線：基準隨慢坡爬升、快照時點錯位、錨點陳舊 |
| 最短警告年齡 P2 | 合成資料有效；Joe 單樹 FP 65 → 171，失敗 |
| 正規化器隨確認重置 P3 | Joe 單樹 FP 65 → 21；成為迴歸基線 |
| 凍結參照 round 1（僅迴歸合成、單樹） | FP 15 → 1（k = 0）／0（k = 500）；機制判準形式上「不確定」 |

另一個被評估並否決的方向是**以自編碼器（AE）取代 ADWIN 的無標籤偵測**。離線探針在每個 GT 漂移前後各取 1000 筆，比較兩種凍結訊號的效果量 d（漂移後平均減漂移前平均，再除以漂移前標準差）：

| 串流 | AE 重建誤差 d | 凍結模型損失 d |
|---|---|---|
| Friedman sudden（n = 6，P(X) 固定） | 0.03 | 3.30 |
| RBF sudden（n = 25） | 0.71 | 2.19（25/25 都比 AE 大） |
| RBF gradual（n = 5） | 0.60 | 1.32 |

我們的漂移大多是純 P(y|X)，AE 在構造上就看不到；在唯一看得到的 RBF 上，它也每一點都輸給凍結模型的損失。

### 2.2 核心動機

**文獻與原始碼調查**（本機報告 `docs_myself/reports/ADWIN 改善誤讀 解法調查.md`，未進 git）帶出三個關鍵事實：

1. **這是移植造成的落差。** MOA 的 `ADWINChangeDetector` 自 commit `585577f`（2017-06-20）起，只在切窗後估計值上升時才回報漂移。HAT、OzaBagAdwin、LeveragingBag 有同樣的檢查，MOA 的 ARF 也透過這個包裝器繼承。官方 ECPF（rand079/CPF）用單一偵測器，預設 DDM；論文實驗用的是 PerfectDetector、HDDM-A、RDDM 與 MagSeed，從未用過雙向 ADWIN。river 的 ADWIN、ARF、SRP 都沒有這道過濾。
2. **原生方向閘從未被測過。** v1–v3 用的都是自訂的純量基準；原生切點的基準是 ADWIN 自己丟掉的舊子窗，在構造上不會隨慢坡爬升、不依賴快照時點，也不會陳舊。
3. **凍結參照有前人工作。** Alippi、Boracchi、Roveri 2013（IEEE TNNLS，循環概念的 JIT 分類器）明言監測持續變好的分類器會造成高誤報，因此改用永不更新的 K0；DriftSurf（Tahmasbi 等，ICML 2021）也凍結可適應模型的快照。所以凍結參照的新意必須收窄，而 E1 是審稿人必然要求的基線。

調查同時在程式中確認了三件會影響設計的事實：
- `update_values` 每次 drift 觸發都重建兩臂，所以任何放在 pipeline 層的壓制，都發生在證據被清空之後。
- warning 開啟期間訓練與對決都暫停。
- 分類的 `extract_signal("error")` 會用 `y_pred` 重算誤差、忽略傳入的 `err`。

### 2.3 預期目標與假說

**總目標：** 消除由改善誤讀造成的 FP，同時不損失 TP。

| 輪 | 假說 | 主要判準（摘要） |
|---|---|---|
| E0 | FP 主要由下降切點觸發（E1 的必要條件） | D1：合計 p_dec(FP) ≥ 0.60，且 FP ≥ 10 的家族各自 ≥ 0.50；D2：下降觸發的 hit 若不少，E2 與 E1 同輪 |
| E1 | 原生方向閘可消除下降觸發的 FP | FP 降 ≥ 40%（MC-RBF ≥ 30%）；TP 損失 ≤ E0 容許量；延遲增加 ≤ 100 步；下降 FP 消失 ≥ 70% |
| E2 | 凍結參照能擋掉 E1 擋不住的上升型誤報（H1），並保住 E1 放棄的漂移（H2） | H1：迴歸 FP 比 E1 少 ≥ 2，且 E0 找到的 20 個追趕事件消失 ≥ 50%；H2：稽核執行上 TP 比 E1 多 ≥ 1 |
| E6 | 在凍結參照上疊加方向閘可再降 FP | 合計 FP 降 ≥ 30%、每家族 TP 損失 ≤ 1、延遲增加 ≤ 100 |
| E7 | 在凍結參照上把 δ 調回 ADWIN 慣用值，可擋掉遠離漂移的誤報 | 3000 步窗：FP 降 ≥ 30%、每家族 TP 損失 ≤ 1、品質不退化 |
| E8 | 「分類用 0.002、迴歸維持原值」在保留資料上成立 | (a) 分類效益重現；(b) 迴歸確實該維持原值 |

## 三、實驗設計與流程

### 3.1 基準對照

**基線設定：** dual ADWIN 讀 leader 的損失，δ 0.05／0.1；迴歸開 P3。

**基線執行：**
- B、MC-syn、MC-RBF 由 E0 以現行程式重跑。
- REG-syn、REG-Joe 沿用封存執行：`outputs/regression_fp_p3_synth`、`outputs/regression_fp_p3_joe_*`，設定 htr-nr、hfr-nr。

**基線可重用的依據：**
- 所有新旗標預設關閉。
- binary byte gate 通過：`run_ecpf_recurring.py` 的 `detector`／`meta_ecpf_gddm`／`meta_ecpf_hier_parallel` 三種模式，在 `recurring_sud_sea100k_g00` 跑 16,000 步，事件 CSV 的 SHA256 與改動前相同。
- 五個家族各抽一次基線重跑，偵測序列都與 E0 或封存逐筆相同。

E6、E7 以 E2-k500 為基線；E8 在保留資料上同時跑 E2-k500 與 E7。

### 3.2 執行流程

1. **登記。** 寫預註冊文件並 commit，再執行任何該輪程式。
2. **實作。** 新機制一律以旗標加入、預設關閉。
3. **閘門。** byte gate、旗標關閉時的基線抽查、E1 自我檢查（人造階梯下降不觸發、上升會觸發）。
4. **執行。** 每個（家族 × 臂）是一格，在 12 核心上平行執行；每格記錄偵測表與逐步 trace。
5. **判定。** `run_e1_e2.py` 的各分析模式依預註冊規則機械化輸出判定，不經人工調整。
6. **Commit** 判定與偵測表。逐步 trace 約 290 MB，可重生，不入庫。

**環境與關鍵超參數：**
- Anaconda Python，river 0.21.2。
- 暖機 200 步、grace 30、clock 32、`ECHO_GAP` 3000、事件配對 ±500 步。
- 其餘超參數見 1.2 的自變數表。

## 四、實驗結果與假說驗證

### 4.1 目標達成度

**已達成：主設定 E2-k500 解決了改善誤讀。**
- 1000 步窗：五家族合計 FP 132 → **28**（−79%），TP 104 → **104**，沒有損失。
- 3000 步窗：FP 75 → **13**（−83%），TP 116 → 113（−3）。
- 它同時解掉第二個混淆：自適應 leader 會把漸變漂移「學掉」，而凍結參照看得到。

**部分達成：**
- 原生方向閘（E1）在分類上幾乎清空 FP，準確率也上升，但會漏掉一半的 RBF 漸變漂移，對迴歸的正規化器追趕也無效。

**未達成：**
- 凍結參照的延遲在多個家族變長（MC-RBF 延遲中位數 692 → 1124 步）。
- Joe 迴歸仍有殘餘 FP（1000 步窗 13 個；3000 步窗 5 個）。
- 二元家族兩種方法都不理想。
- 疊加方向閘（E6）與 δ 校準（E7、E8）都依登記判為不採用。

### 4.2 假說驗證結果

**成功驗證：**
1. **分類的 FP 主要由下降切點觸發（E0）：** 分類三個家族 p_dec(FP) 為 0.83–0.91。E1 在這些家族消除了 85–100% 的下降觸發 FP。
2. **迴歸的誤讀被正規化器偽裝成上升（E0 的 M3）：** 迴歸 49 個 FP 中，有 45 個在切窗前後的原始殘差持平或下降；其中 24 個正規化後看起來是上升，就有 20 個屬於這種追趕。
3. **H1 成立：** 迴歸 FP 從 E1 的 34 降到 E2-k0 的 17，追趕事件有 80% 消失。
4. **H2 成立：** 在 16 個含下降觸發命中的稽核執行上，TP 從 E1 的 24 升到 E2-k0 的 34。機制見 4.3.3：RBF 漸變漂移的命中數，E1 只剩一半，凍結參照全數抓到，這與 DriftSurf 凍結快照的理由一致。
5. **E6 的「不採用」預測得到證實：** 前置重播顯示殘餘 FP 只有 7/28 是參照空間的下降切點；實際閉環只少了 3 個。
6. **Joe 殘餘 FP 大多是晚到的真命中（重新計分）：** 計分窗放寬到 3000 步後，E2-k500 的 REG-Joe FP 13 → 5、TP 21 → 29。

**推翻或修正：**
1. **「連鎖反應的再觸發多半也是下降」無法檢驗：** P3 開啟後，連鎖候選只有 3 個，不到判定門檻。
2. **「兩臂 `clock` 同步是 1 筆緩衝的原因」被修正：** 兩臂確實按構造同相，但以每步評估的影子臂量測，只有 45% 的零領先確認能提早 ≥ 16 步（門檻 50%），綁定約束在門檻本身，不在評估時點。
3. **「δ 在參照空間是乾淨的槓桿」只部分成立：** E7 擋掉了 69% 遠離漂移的誤報，但弱漂移（二元、Joe 迴歸）的召回同時下降。
4. **「按任務切分 δ」不成立：** 保留資料上分類效益沒有整體重現，唯一的失敗是二元 −2 TP。兩批資料一致的分界其實是「多類別」對「二元與迴歸」，而不是分類對迴歸。
5. **k = 500 相對 k = 0 的優勢依計分窗而定：** 1000 步窗下 k = 500 保留（FP 28 對 30，恰好壓在門檻）；3000 步窗下 k = 0 的 TP 較多（119 對 113）。

## 五、局限性與衍生問題

### 5.1 邊界條件與局限

1. **只有合成資料。** 除 RBF 外，所有生成器都固定 P(X)，漂移只是 P(y|X) 的改變。結論在真實串流、共變量漂移為主、或標籤延遲的情境下未經驗證；本管線全程假設標籤即時到達。
2. **決定性單次執行。** 每個（串流 × 學習器）只有一次執行，沒有種子變異的估計，也沒有顯著性檢定。二元只有 6 個命中、REG-syn 只有 3 條串流，這些家族的判定對單一事件很敏感。
3. **結論依賴計分窗。** 1000 步與 3000 步會改變 E6 以及 k = 0 對 k = 500 的相對結論（4.2 推翻或修正第 5 點）。本報告的正式判定一律依各輪登記的計分窗。
4. **結論依賴 river 版本。** river 0.21.2 與 0.23.0 的 ADWIN 在同一輸入上觸發時點不同（見 5.2 第 1 點），所有數字只在 0.21.2 下成立。
5. **凍結參照的代價：**
   - 延遲變長（MC-RBF、MC-syn、REG-syn 皆然）。
   - k = 0 在 REG-syn 上 MAE 變差（3.08 對基線 2.81）。
   - 每一步多做一次模型預測。
6. **標籤依賴啟發式。** echo／orphan 的分類來自 `classify()` 的時間規則；不同的規則會改變 FP 的分類，但不改變 FP 總數。
7. **登記時序。** E0 與 E1／E2 的預註冊 commit 晚於執行（判準在本機先寫定）；E6 起才是「先 commit 後執行」。
8. **偵測器家族。** 只檢驗了 dual ADWIN 路徑，其他偵測器家族（SEED、HDDM、HCDT 等）沒有對應結論。

### 5.2 衍生的新問題

1. **river 版本造成的重現性風險。** 封存實驗都是用 Anaconda 的 river 0.21.2 跑的，repo 的 `.venv` 卻是 0.23.0，而 `requirements.txt` 只寫 `river>=0.21`。同一條輸入，0.21.2 在 6055 觸發（與記錄相符），0.23.0 在 5959 觸發。
2. **分類的 `extract_signal("error")` 會用 `y_pred` 重算誤差。** 只替換 `err` 會不出錯地繼續讀 leader 的誤差。這是一個容易踩到的陷阱，本輪已處理。
3. **`update_values` 每次 drift 觸發都清空兩臂。** 過去所有在 pipeline 層的壓制（冷卻、方向閘 v1–v3、P2）都在證據清空之後才發生，依賴這類壓制的舊結果值得複核。
4. **改善開啟的 warning 會暫停訓練。** MC-syn 有 12.7% 的步數花在這種暫停上。E1 在多類別的準確率提升，部分可能來自這裡，而不只是 FP 減少。
5. **命中數被灌水。** 寬計分窗內剛好出現的改善觸發會被算成命中（MC-RBF 漸變 10 個中有 8 個），所以基線的 TP 高估了真正的偵測能力。
6. **處方不跨運作條件轉移（第五次出現）。** δ 0.002 在多類別兩批資料上一致有益，在二元與 Joe 迴歸上一致損害召回。分界看起來是漂移在參照損失上的訊號大小，不是任務類型；但這是事後解讀。
7. **分析腳本的 bug（已修正）。** 沒有任何確認的執行不會出現在偵測表中，曾被漏算。修正後 TP、FP 不變，只修正了 MC-RBF E1 的平均準確率（0.716 → 0.709）。

### 5.3 下一步行動

1. **鎖定 river 版本。** 在 `requirements.txt` 寫死 `river==0.21.2`，確保重現性。
2. **決定計分慣例。** 若改採 3000 步窗，或兩者並報，應在新口徑下重新登記並重審 E6 與 k = 0 對 k = 500。
3. **縮短凍結參照的延遲。** 候選方向是參照品質與新鮮度，例如以資料驅動的平台判準決定何時再凍結，或參考 DriftSurf 的定期刷新。v4 的 z_ref 機制判準門檻仍待改登為以 GT 為錨的統計量，並補做 `analyze_reference_signal.py`。
4. **「只對多類別收緊 δ」**（可選）。E8 的保留資料已用過，必須準備全新的保留資料（例如 RBF g02、合成 seed 2042）並重新登記；這會是同一想法的第三次檢驗，報酬遞減。
5. **Joe 迴歸的殘餘。** 依敏感度分層（low／medium／high）分析晚到的命中與弱漂移的關係。
6. **外部效度。** 加入至少一個真實世界串流，並涵蓋共變量漂移。
7. **論文整合：**
   - 分析章寫入改善誤讀的機制（含正規化器追趕與漸變遮蔽）。
   - 方法章寫入凍結參照與 E1 基線。
   - E6、E7、E8 寫成「處方隨運作條件而異」的敏感度分析。
   - 凍結參照的新意收窄為四點：在循環概念 meta-learner 中為餘波、孤兒、連鎖反應命名並量測；受控的「有閘對無閘」ADWIN 比較；迴歸落地；以及保住雙向語意（由 H2 支持）。
