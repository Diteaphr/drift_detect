# V1＋E9 預註冊：E1 與 MOA 的一致性驗證、官方 ECPF 式偵測器

**登記：** 2026-09-28，以本文件的 commit 為準。V1 與 E9 的任何執行都在這個 commit 之後。

**動機：** 「移植造成的落差」這個說法引出兩個問題。
- E1 真的等於 MOA 的 ADWIN 嗎？
- 為什麼不直接用官方 ECPF 的偵測器？

E1、E2 的結論要站得住，這兩個問題都得有實測答案。

## V1：E1 的偵測器是否忠於 MOA

- **對照：** MOA 的 `ADWINChangeDetector`，經 CapyMOA 0.14.0（內含 moa.jar）呼叫。CapyMOA 要求 numpy 2.x，因此裝在 scratchpad 的**獨立 venv**；主環境（river 0.21.2、numpy 1.x）不動。
- **方法：** 離線重播，與 E0 同法。
  - 取 E1 五個家族的逐步 trace（`outputs/e1_e2/*/E1/signals`，偵測器輸入欄為 `err`），餵給 MOA 的兩臂：warning δ 0.1、drift δ 0.05。
  - 重建時點**照 E1 記錄的觸發**：每次 drift 觸發後兩臂重建；每次 warning 觸發後重建 warning 臂。後者是 ARF 的慣例，也等同 river 觸發後自行清空。
  - 兩邊因此看到同樣的輸入與同樣的視窗起點，差異只可能來自偵測器本身。
- **指標：** 每一臂分別計算兩個方向的比例：
  - E1 的觸發中，MOA 在 ±32 步內（一個 clock）也觸發的比例；
  - MOA 的觸發中，E1 在 ±32 步內也觸發的比例。

  另報兩者在同一步觸發的比例。
- **判準：** drift 臂兩個方向的比例都 ≥ 0.90，就判 E1「忠於 MOA」。否則報告差異來源（river 的 `grace_period` 30 對 MOA 最小視窗 10、clock 對齊、bucket 實作），並把 E1 的結論改述為「river 的 ADWIN 核心加上 MOA 的方向語意」。
- **預測：** 大部分觸發對得上；少數差異集中在每個視窗的前 30 步（兩者的最小視窗不同）。

## E9：官方 ECPF 式單一偵測器

- **設計：** 只在分類家族上跑（B、MC-syn、MC-RBF），串流、學習器、步數與 E0–E7 相同。原因是 DDM 與 HDDM-A 只收 0/1 誤差；ECPF 論文本身也只做分類。
- **兩臂：**
  - **E9d：** river `DDM`（warm_start 30、warning 2.0、drift 3.0，與 MOA 預設相同）。官方實作 rand079/CPF 的預設偵測器就是 DDM。
  - **E9h：** river `HDDM_A`（drift_confidence 0.001、warning_confidence 0.005，單側）。ECPF 論文的敏感度分析用過它。
  - 兩臂都讀 **leader 的 0/1 誤差**，採**官方語意**：
    - warning 就是偵測器目前是否處於 warning 區；
    - 離開 warning 區而沒有漂移時，關閉 warning 並丟掉緩衝；
    - 漂移之後偵測器重設。
  - warning 期間暫停訓練的行為與其他各臂相同，不另外更動。
- **排除：** RDDM 與 MagSeed 不跑。river 沒有 RDDM；repo 裡的 RDDM 與 `HDDM_A` 是簡化實作，不忠於原版（repo 的 `HDDM_A` 只判斷 `abs(p_short − p_long) >= 0.1`，而且是雙向的）。MagSeed 的原始碼找不到。
- **比較對象：** base（E0）、E1、E2-k500，都沿用既有執行。
- **要檢驗的主張：** 問題出在偵測器**看的訊號**（一個會學習的模型），不在偵測器演算法。
- **判準（各偵測器分別判定）：**
  - **P1：** 三個分類家族合計的 FP（1000 步窗）≤ base 的 50%（base 合計 83，所以 ≤ 41）。單側偵測器應該能擋掉改善誤讀。
  - **P2（關鍵）：** MC-RBF 漸變串流的命中數 ≤ 8（base 10、E1 5、E2-k500 11）。讀 leader 誤差的偵測器，應該看不到被學習器學掉的漸變漂移。
- **結論規則：**

  | 情況 | 結論 |
  |---|---|
  | 兩個偵測器 P2 都成立 | **主張成立**：換偵測器演算法補不了這個盲點，凍結參照的必要性得到支持 |
  | 任一偵測器漸變命中 ≥ 11，而且 P1 成立 | **主張被推翻**：單靠換偵測器就能解決，凍結參照的貢獻必須重新定位 |
  | 其他情況 | 如實報告，不下結論 |

- **照常報告：** 1000 與 3000 步窗的 TP／FP、延遲中位數、準確率，全部與 base、E1、E2-k500 並列。
- **閘門：** 新旗標 `ecpf_zone_detector` 預設關閉；binary byte gate 必須逐位元相同；旗標關閉時抽查一條分類基線，必須重現 E0；零件自我檢查：人造誤差率從 0.1 跳到 0.5 時必須先 warning 再 drift，誤差下降時不得觸發。
