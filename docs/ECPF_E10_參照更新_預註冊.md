# E10 預註冊：凍結參照的更新規則（限齡刷新、leader 守衛）

**登記：** 2026-09-29，以本文件的 commit 為準；本 commit 同時納入 E10 用到的新資料子集。E10 的任何程式改動與執行都在這個 commit 之後。
**目的：** 修正 E2-k500 更新參照的規則，讓它在長串流上的召回恢復，同時保住它壓低 FP 的效果。
**判定資料：** E10 是看過 A2 的結果才設計的，所以照 E8 的原則，**只在前面各輪（E0–E9、A1、A2）都沒用過的資料上判定**。A1、A2 與 INSECTS 只當開發資料。

## 背景：開發資料上的診斷（A2 之後的事後分析）

E2-k500 只在確認漂移後 500 步重新凍結參照，所以有兩個後果：

1. **暖機參照太弱。** 第一次確認之前，參照是暖機結束時（第 200 步）凍結的模型。gas_sensor 有 128 特徵、6 類，這個模型太弱；A2 的 24 條 gas 串流有 9 條從頭到尾沒有確認過。
2. **漏抓會連鎖。** 漏抓一次之後，參照停在舊概念上，後面的漂移也跟著漏抓。A2 逐一檢查 GT 漂移：

   | 漂移發生時參照的年齡 | 漂移數 | base | E1 | E2-k500 |
   |---|---|---|---|---|
   | 2k–10k 步 | 85 | 67 | 51 | 67 |
   | ≥ 10k 步 | 87 | 75 | 61 | 47 |

   INSECTS abrupt 的準確率損失也是同一個原因：參照 13,634 步沒更新，看不到兩處類別組成變化。

開環估計（各臂在自己的執行中抓到就算）：E1 與 E2-k500 的命中聯集，在 INJ-gas、SYN2-B、SYN2-MC、SYN2-REG 分別是 15、49、35、48（base 為 15、44、35、53）。

## 臂

| 臂 | 定義 |
|---|---|
| base | 雙向 dual ADWIN 讀 leader 的損失（對照臂，不判定） |
| E1 | base 加上原生方向閘（對照臂，不判定） |
| E2-k500 | 凍結參照，k = 500（對照臂，不判定；兩個新臂都從它出發） |
| **E10a 限齡刷新** | E2-k500 加上一條規則：參照的年齡達到 **R = 5000** 步、而且沒有開著的 warning 時，從當前的 leader 重新凍結參照，並重建參照的兩臂 ADWIN（與 k = 500 的切換相同）。有 warning 開著時，等它結束再刷新。暖機時凍結的第一個參照也適用 |
| **E10b leader 守衛** | E2-k500 加上第二組偵測器：E1 的單側 dual ADWIN（δ 0.05／0.1），讀 leader 自己的損失。兩組任一發出 warning 就開啟 warning；warning 開著時兩組任一發出 drift 就確認。每次確認後兩組都重建；k = 500 的切換只重建參照那一組 |

- **參照年齡**指參照上次凍結後經過的步數（trace 的 `ref_age`）。
- **R = 5000 的來源：** 依開發資料選定（參照年齡在 10k 步以下時，E2-k500 的命中與 base 相同），登記後不再調整。
- **其餘設定**與 E0–E9、A1、A2 相同：δ 0.05／0.1、warning 期間暫停訓練、river 0.21.2；迴歸開 P3。

## 計分

同 A2：標籤一律用 `classify()`，判準用 3000 步窗；漂移前 FP 只用於 INJ-gas。

## 判準（E10a、E10b 各自判定；與 A2 的 P1–P4 相同）

- **P1（INJ-gas）：** 合計漂移前 FP ≤ base 的 30%。base 合計至少要有 10 個，這條才可判定。
- **P2（INJ-gas）：** 合計 TP@3000 ≥ base 的 90%。
- **P3（SYN2，B、MC、REG 三組分開判）：** FP@3000 ≤ base 的 50%，而且 TP@3000 ≥ base 的 90%。該組 base 的 FP@3000 少於 6 個時，FP 部分不可判定，只判召回。
- **P4（準確率護欄，四組分開判）：** 分類的平均準確率 ≥ base − 0.01；迴歸的平均 MAE ≤ base × 1.02。
- **結論規則：**
  - **分類採用：** P1、P2、P3-B、P3-MC，以及 SYN2-B、SYN2-MC、INJ-gas 的 P4 全部成立；
  - **迴歸採用：** P3-REG 與 SYN2-REG 的 P4 都成立；
  - **兩臂在同一種任務都採用時：** 選該任務合計 TP@3000 較高的一臂；相差 2 個以內時，選較簡單的 E10a；
  - **兩臂都不採用時：** 照實報告 E2-k500 在長串流上的召回問題仍未解決。
- **機制檢查（照常報告，不影響採用）：**
  - 在 E2-k500 漏抓、而且漂移發生時其參照已 ≥ 10k 步的 GT 上，E10a、E10b 各抓回幾個。
  - E10a 的刷新次數；E10b 由守衛觸發的確認數。

## 事前預測（不影響判定）

- **E10b：** 分類預期採用。迴歸預期因 FP 不採用，因為守衛讀的是 leader 正規化後的誤差；E0 已發現，改善會被正規化器的追趕偽裝成上升。開發資料的開環估計是 REG 的 FP 最多到 E1 的 16 加 E2-k500 的 8。
- **E10a：** 召回預期明顯高於 E2-k500。主要風險是刷新剛好發生在漸變途中，讓參照吸收一部分漂移。
