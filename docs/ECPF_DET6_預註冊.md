# DET6 預註冊：慢速漸變上的 E10bFT 對 HDDM-A

**登記：** 2026-10-18（Asia/Taipei），以本文件的 commit 為準。兩組在判定資料上的任何執行，都在本文件與計分腳本提交之後才開始。本文件提交後不改寫，偏離一律追加在末尾「修訂」。

**頂層問題：** DET3 到 DET5 的四個主判定，比的漂移過渡期都在 2500 步以內，E10bFT 的超額命中都比 HDDM-A 少。四個 ΔX 的 95% CI 都整段在 0 以下。2026-10-14 有一次沒登記的探索檢查，用的是 3 條開發串流，過渡期 4000–16000 步，結果方向相反：森林上 E10bFT 抓到 26 個漂移中的 25 個，HDDM-A 抓到 13 個。單棵樹上是 24 對 17。那次檢查沒有 CI，資料在設計時看過。本輪用新產生的慢速漸變串流回答兩個問題：

1. 過渡期是 4000 到 16000 步時，E10bFT 的偵測有沒有比 HDDM-A 好？
2. 如果比較好，誤報和準確率付出多少代價？

## 一、名詞

以下名詞的定義和 [DET3 預註冊第一節](ECPF_DET3_預註冊.md)完全相同，計分沿用同一組函式：警報、GT、命中、誤報（FP）、碰運氣的期望命中（C）、超額命中（X）、平均偵測延遲（MDT）、整條串流準確率。本輪另外用到：

| 名詞 | 意思 |
|---|---|
| 過渡期 | 從 GT 起點 `d_s` 到終點 `d_e = d_s + w`。過渡期內的第 t 筆，以 `(t − d_s) / w` 的機率取自新概念，否則取自舊概念。`d_s` 之前全部取自舊概念，`d_e` 之後全部取自新概念 |
| 過渡寬度 w | 4000、8000 或 16000 步。一種寬度是一個 cell，記為 `w04000`、`w08000`、`w16000` |
| 主窗 | `[d_s, d_e + 1000]`，含端點，也就是整個過渡期再加 1000 步。窗長是 w + 1000 |
| 短窗 | `[d_s, d_s + 1000]`，也就是 DET3 到 DET5 的主窗 |
| trial | 同一個 cell 以不同亂數產生的第幾條串流，編號 g00–g49 |
| 超出碰運氣 | 一組在一個母體上的 X（全部串流合計）的 95% CI 下界大於 0 |

窗越長，C 越大，因為警報碰巧落在窗內的機會變大。所以主窗不會讓一個誤報多的偵測器白白多得分。

## 三、資料

| cell | 過渡寬度 | 判定用 trial | 條數 | GT 數 | 每條長度 |
|---|---:|---|---:|---:|---:|
| `w04000` | 4,000 | g00–g39 | 40 | 120 | 100,000 |
| `w08000` | 8,000 | g00–g39 | 40 | 120 | 100,000 |
| `w16000` | 16,000 | g00–g39 | 40 | 120 | 100,000 |
| 合計 | | | 120 | 360 | |

- **產生器：** `scripts/generate_det6_streams.py`，本輪新寫，和本文件一起提交。
  - 概念用 river 0.21.2 的 `RandomRBF`：4 類、10 個特徵、50 個質心。這和 Joe 的多類別產生器、E9 的開發串流相同。
  - 每條 100,000 筆，有 3 個漂移，每次都換成一個新的概念，也就是每條 4 個概念、不重複出現。
  - 過渡是線性的，見第一節。
- **漂移位置：**
  - 第一個 `d_s` 至少在第 10,000 筆。
  - 兩個漂移之間，前一個 `d_e` 到下一個 `d_s` 至少 10,000 筆。
  - 最後一個 `d_e` 之後至少還有 5,000 筆。
  - 剩下的筆數用多項分布隨機分到這 4 段空檔。
  - 所以任兩個主窗都不重疊，每兩個漂移之間都有一段穩定期，可以計算誤報。
- **亂數：** 每條串流的種子是 `sha256("DET6|<寬度>|<trial>")` 的前 8 個十六進位數字，只由 cell 和 trial 決定，所以在任何機器上都能重新產生。特徵值寫到小數第 6 位。
- **和開發串流的差別：** 2026-10-14 的開發檢查用 Joe 的 `recurring_gradual_rbf4_100k_g00`，有 high、medium、low 三種，過渡寬度分別是 4000、8000、16000。那三條是用 river 的 `ConceptDriftStream` 做 S 形過渡，漂移位置隨機，可能重疊；low 那條的窗幾乎蓋滿整條串流。本輪改成線性過渡、位置不重疊、每條固定 3 個漂移，理由有兩個：
  - 窗從 `d_s` 開始算，線性過渡在 `d_s` 之前完全沒有新概念，起點是明確的。
  - 窗不重疊，誤報和 C 才算得清楚。
- **檔案：**
  - CSV 不進 git，放在被忽略的 `data/det6_slow_gradual/`，每條約 9.25 MB。
  - node2 上由啟動腳本重新產生，旁邊有同名的 `_drift_times.txt`（GT）和 `.json`（cell、種子、GT）。
  - 登記前在 lucas-jang 上產生過一次，算出判定用 120 個 CSV 的合併雜湊。算法是 `generate_det6_streams.py --digest`：每個檔案寫成「檔名 sha256」一行，排序後再取一次 sha256。結果是 `a815e10579f284c05b040cedc4fedd545b7ac5838d1c8590854ea3cc1c579566`。
- **登記檔：** 本輪在 `configs/datasets_0921.json` 新增 `synthetic_slow_gradual` 一項（role `dev`，comparable 為 false），其他項目不動。這一項只在這條本機分支上；合併到 main 之前要先和 Joe 確認。
- **g49：** 只用在閘門 G3，本輪不判定，之後任何輪次也不拿來判定。g40–g48 不產生，留給之後的輪次。
- **座標和計分範圍：** 和 DET3 的 synthetic 層相同。
  - 產生的串流不刪列，輸入座標就是輸出座標。
  - 暖機 200 筆之後的警報都計分。
  - 第一個漂移在第 10,000 筆之後，所以 360 個 GT 全部計分。

## 五、判定規則

### 主判定：單棵樹，120 條，主窗

| 條件 | 量 | 成立 | 不成立 | 持平 |
|---|---|---|---|---|
| P1 誤報 | `ΔFP = FP(E) − FP(H)`，120 條合計 | 95% CI 上界小於 0 | 下界大於 0 | 其餘，含碰到 0 |
| P2 超額命中 | `ΔX = X(E) − X(H)`，120 條合計，主窗 | 95% CI 下界大於 0 | 上界小於 0 | 其餘，含碰到 0 |

**CI 的算法：**
- 以串流為單位、兩組配對、有放回抽樣 10,000 次，種子 `20261012`，取第 2.5 和 97.5 百分位，和 DET1、DET3 到 DET5 相同。
- 依過渡寬度分三層，每層 40 條，在層內抽樣後合計。
- 各組自己的 X 的 CI 用同一批抽樣算。

| P1 | P2 | 結論 |
|---|---|---|
| 成立 | 成立 | E10bFT 優於 HDDM-A |
| 不成立 | 不成立 | E10bFT 不如 HDDM-A |
| 一個成立、一個不成立 | | 有得有失：照實寫哪一項較好、哪一項較差，不下勝負結論 |
| 任一持平 | | 持平 |

**可判定性：** 和 DET5 相同。如果兩組的 X 都沒有超出碰運氣，P2 記「不可判定：兩組的命中都沒有超出碰運氣」，結論改寫成「兩組的偵測都接近碰運氣；誤報 E 較少、較多或持平」，由 P1 決定。

**結論可以怎麼寫：**
- 結論用語只看上表。
- 範圍限於「合成 RandomRBF 資料、線性過渡 4000 到 16000 步、單棵 Hoeffding Tree、警告期間暫停訓練」。
- 如果 P2 成立而 P1 持平，結論是持平。可以照實寫「超額命中較多（P2 成立），誤報沒有差別」，但不能寫「偵測優於 HDDM-A」。
- 如果 P2 成立而準確率較差，要和 H3 一起寫成「抓得較多、準確率較差」。

### 次要判定

以下兩個用同一套 P1、P2 和可判定性規則，各自判定、各自標示「次要」，不改變主判定：

1. **森林，120 條，主窗。**
2. **單棵樹，120 條，短窗。** 這讓本輪能和 DET3 到 DET5 的主判定接起來。

主判定和次要判定方向相反時，兩邊都保留、都寫出來。

### 次要假說

- **H2 各過渡寬度。** 單棵樹在每種寬度各 40 條上分開算 `ΔX`，用主窗。CI 下界大於 0 記「主方法較多」，上界小於 0 記「主方法較少」，其餘記「沒有差別」。森林也分寬度算，只描述。
- **H3 準確率。** `Δacc` 是兩組整條串流準確率的差，以可計分預測數加權，每次抽樣重算。CI 全正記「較好」，全負記「較差」，其餘記「持平」。在主判定和兩個次要判定的母體上各算一次。

### 只描述、不判定

- 森林在短窗下的 P1、P2。
- 各寬度、各學習器的 FP、命中、C、X、MDT，主窗和短窗都列。
- 警告的開啟、確認、逾時、離區關閉次數，訓練暫停的總步數，執行時間。
- 和 2026-10-14 開發檢查的命中數並排。資料和計分時間點都不同，只比方向，不做檢定。

## 六、事前預測

- **主判定：** P2 成立，也就是 E 的超額命中較多；P1 持平。依上表結論是「持平」，但 P2 單項成立。
- **森林：** 同主判定，P2 成立、P1 持平。
- **短窗：** 不可判定，兩組都接近碰運氣。根據是開發檢查在短窗下所有組只命中 0 到 6 個。
- **H2：** 寬度越大，ΔX 越大；`w16000` 是「主方法較多」。
- **H3：** 單棵樹和森林都是 E 較差。根據是開發檢查裡 HDDM-A 的準確率較高。

## 十、限制

- **合成資料：** 只有一種產生器（RandomRBF，4 類）。過渡是線性的，每條 3 個漂移，每次都換成新概念、不會重複出現。結果不能直接推到真實資料。
- **寬度只有三種，** 而且都在 4000 步以上。本輪沒有 1000 步的對照，1000 步的比較是 DET3 到 DET5 做的，資料不同。
- **主窗比較長：** 各寬度的窗長不同，C 也跟著不同。CI 依寬度分層算，但三層合計時，寬的那層份量比較大。
- **過渡形狀和開發檢查不同：** 開發檢查是 S 形過渡，本輪是線性。開發檢查的方向不一定會重現。
- **主方法看過這類資料：** 主方法在 E 系列發展時用過同一類 RandomRBF 資料。
- **先看過結果：** 本輪是看過 DET5 和開發檢查之後才決定跑的。用新的串流和事先定好的規則來降低這件事的影響，但無法完全排除。
- **登記檔的新項目只在本機分支上。**
- **沒調參：** HDDM-A 用 MOA 預設參數，主方法的參數是在別的資料上定的，兩邊都沒有在這批串流上調參。
