Model Pool 淘汰機制實驗

把 model pool 的淘汰規則從「看正確率」改成同時考慮記憶體，比較 6 種新機制在 2 種骨幹上的表現。重點是 pool 記憶體的 peak：省下多少，又付出多少正確率。

真實資料集 electricity、insects_abrupt_balanced、insects_incremental_abrupt_reoccurring_balanced、insects_incremental_reoccurring_balanced 合成資料集 synthetic_binary 的 recurring 子集（10 條資料流，dev 用，不可比） 方法 38 組 preset，共 532 runs commit ee3e39d 機器 Apple M5 / 24 GB；真實資料一次只跑一個 run，合成資料 3 條並行（時間僅供參考）

重點

peak 記憶體 −54% 到 −70%

e10bft_rent_l10 在 4 個真實資料集的 pool peak（相對主方法），合成資料 −27%。density_b2 為 −59% 到 −78%。

平均記憶體 −34% 到 −79%

e10bft_rent_l10 與 density_b2 在 5 個資料集的平均 pool 記憶體（相對主方法）。

正確率 ±1.5 點內

38 組相對主方法介於 −1.43 到 +1.39 點。4 個可比資料集的 Friedman p = 0.32，主方法對每個方法的 Wilcoxon（Holm 校正）p 都是 1。

原因 重用價值 < 0

4 個真實資料集上，重用舊 model 平均都輸給新 model。e10bft 骨幹上「完全不留 pool」最多也只掉 1.19 點。

實驗設定與指標

每種機制都是一個獨立方法，各自掛在兩種骨幹上：e10bft（主方法的偵測流程，只換 pool 淘汰規則）與 ecpf（原版 ECPF + dual ADWIN）。參考組是主方法 e10bft、ecpf_paper 與 ecpf_reuse_value。

正確率與 pool 指標來自 benchmark runner 的 runs.csv 與每個 run 的 pool_metrics.json、pool_trace.json。頁面上的 Δ、排名與綜合分數是用這些數字在頁面裡換算的，定義如下。

合成資料集有 10 條 recurring 資料流（SEA 與 Hyperplane 產生器），表格與圖 1、3、4 用的是 10 條的平均，peak 是各條 peak 的平均。它是開發用資料集，不能和文獻比較，但可以合法用來挑參數。

正確率
prequential accuracy，整段資料流逐筆先預測再學習。
peak KB
整段資料流中，pool 裡所有 model 大小總和的最大值（只算樹本身）。下限大約是一棵 leader 樹的大小。
平均 KB
同一個總和在整段資料流上的時間加權平均。
Δ
相對主方法 e10bft 的變化：正確率用百分點，記憶體用百分比。
綜合分數
同時權衡正確率與記憶體，0 到 1，越高越好。每個資料集內：正確率分 = (acc − 最低) ÷ (最高 − 最低)；記憶體分 = (ln 最大 KB − ln KB) ÷ (ln 最大 KB − ln 最小 KB)；綜合分數 = (1 − w) × 正確率分 + w × 記憶體分，再對所有資料集取平均。w 可以在圖 4 調整。這是直覺排序用的經驗分數，不是統計檢定。
恢復正確率
每次 drift 警報後 500 筆的正確率。
後悔率
drift 時，最近被丟掉的 model 比 pool 裡最好的還好的比例。
重用價值
重用的舊 model 在 drift 後 500 筆比新 model 多答對幾筆，負數代表重用反而較差。

怎麼讀：同一個資料集裡，38 組的正確率最多只差 0.9 到 1.9 個百分點，peak 記憶體卻差 2.9 到 9.2 倍，所以 w 一高分數就由記憶體主導。w = 0.5 用 peak 時，第一名是 entry_f15 / f30（等於不留 pool），主方法排第 36；w ≤ 0.25 時第一名是 e10bft_rent_l2，主方法排第 14 到 16。選哪個 w，取決於願意用多少正確率換記憶體。

排序依據

限制與下一步

關於 peak 的觀察

  • peak 的下限大約是一棵 leader 樹：只留 leader 的 entry_f15（e10bft 骨幹）peak 是 electricity 244 KB、insects_abrupt 1,343 KB、insects_inc_abrupt_reoc 674 KB、insects_inc_reoc 1,110 KB、合成資料 342 KB。
  • insects_abrupt 上幾乎所有以重用價值為基礎的方法 peak 都是 2,687 KB（−59%）。這個資料集 drift 少，差別來自共同的重用價值規則，不是各記憶體機制本身。
  • 兩個 recurring 的 INSECTS 資料集最能看出差別：rent_l10 的 peak 是 −67% 與 −70%，density_b2 是 −78% 與 −67%。
  • 原版規則壓不住 peak：跨資料集 peak 平均排名，主方法第 35.8、ecpf_paper 第 34.8（共 38 組）。
  • 合成資料是唯一重用價值為正的資料集（主方法平均 +1.16，71% 的重用是正的），但每條資料流平均只有 5.5 次 drift。多數方法的正確率與主方法完全相同；壓 peak 最多的方法（rent_l10 −27%、density_b2 −39%）掉 0.14 與 0.38 點。

這次結論的限制

  • rent_l2、rent_l10 原本是看 report 資料集挑的。這次加入的合成資料是 dev 資料集，可以當獨立檢查：rent_l10 在合成資料上 peak −27%、正確率 −0.14 點；rent_l2 幾乎沒有變化（peak −3%，正確率 0.00）。
  • 4 個可比資料集的 Friedman p = 0.32；加入合成資料後 p = 0.006，但這只代表 38 組的排名不完全相同，主方法對每個方法的 Wilcoxon（Holm 校正）都不顯著，不能宣稱哪個方法較準或較差。
  • 綜合分數的 0 到 1 是相對這 38 組的最好與最差，換一組方法比較時分數會變。
  • 程序層級的 RSS 與 RAM-Hours 會包含為了算後悔率而保留的已淘汰 model，不能拿來比 pool 記憶體；請看 pool KB 與最終 model 大小。合成資料是 3 條並行跑的，執行時間只能當參考。

建議的下一步

  • 從 pool 的 snapshot 拿掉沒用到的 sample buffer：每個存放的 model 多帶 1 MB（electricity，8 個特徵）到 3.7 MB（INSECTS，33 個特徵），拿掉不會改變任何預測。
  • 若以 peak 為主要目標，可以直接用「peak KB 上限」當淘汰條件（目前的上限是相對 leader 大小）。
  • 固定 e10bft_rent_l10 與 e10bft_rent_l2，到 airlines_full、covertype_full 等較長的資料流上驗證。
  • 用 block bootstrap 做非劣性檢定，正式回答「哪些方法沒有比主方法差」，再在其中挑 peak 最小的。
  • 入場費改成低於新 leader 寬限分數 15（例如 1、3、8）重測。
