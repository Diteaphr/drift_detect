## 一、前置定義與上下文

### 名詞

| 名詞 | 意思 |
|---|---|
| 警報 | 系統判定發生漂移並回報的那一步 |
| GT | 資料集附的漂移標準答案，每個漂移有一個起點 `d_s` |
| 主窗 | 每個 GT 起點後的 1000 步，`[d_s, d_s+1000]`，含端點 |
| 命中 | 一個 GT 的主窗內至少有一次警報，每個 GT 最多算一次 |
| 誤報（FP） | 落在所有主窗之外的警報數 |
| 碰運氣的期望命中（C） | 假設警報和漂移無關、以該次執行自己的誤報率隨機出現時，預期會落進主窗的 GT 數 |
| 超額命中（X） | 命中數減 C |
| 平均偵測延遲（MDT） | 被命中的 GT，從起點到主窗內第一次警報的步數，取平均 |
| 整條串流準確率 | 每筆先預測再學習，所有可計分預測中正確的比例 |
| 警告 | 偵測器進入「可能漂移」狀態。兩組在警告期間都暫停訓練主模型 |
| 訓練暫停步數 | 處於警告狀態、主模型沒有學習的總步數 |

計分函式沿用 DET1，定義和 DET1 完全相同。

### 變因

- **自變因：** 偵測方式，兩組。
  - **DET3-E** = preset `e10bft`。兩個 ADWIN 讀凍結參照模型的損失，加上只認「變差」的 leader 守衛，警告超過 1000 步未確認就關閉。
  - **DET3-H** = preset `det1_zone_hddm_a_lw0`（DET1 的 A3）。HDDM-A 的 warning 區開警告、drift 區確認，參數是 MOA 預設值。
- **判定用的依變因：** FP 和 X。
- **只描述、不判定的依變因：** 命中、MDT、準確率、kappa、警告次數、訓練暫停步數、執行時間。
- **控制變因：** 單棵 Hoeffding Tree、ECPF 嚴格替換、ECPF 淘汰規則、模型池上限 10、暖機 200 筆、警告期間暫停訓練、`river==0.21.2`、同一台機器、同一個 commit。兩個 preset 檔沒有修改，沒有調任何參數。

### 資料

| 層 | 串流 | 條數 | GT 數 | 對主方法是不是新資料 |
|---|---|---:|---:|---|
| injected | `injected_paper_electricity`，8 個 cell 各取 g00–g19 | 160 | 160 | 是 |
| synthetic | `synthetic_multiclass` 全部 | 40 | 303 | 不是，主方法的設計接觸過 |
| INSECTS | 五個 `insects_*_balanced` | 5 | 10 | 不是，兩組的結果登記前都看過 |

injected 的警報、GT 和串流長度用原始輸入座標，前 25% 的警報不計分。其餘資料暖機 200 筆之前的 GT 不計分。INSECTS 有一條沒有可計分的 GT，只算準確率。

### 判定規則

- **P1 誤報：** `ΔFP = FP(E) − FP(H)`。95% CI 上界小於 0 記「成立」，下界大於 0 記「不成立」，其餘記「持平」（含 CI 邊界剛好是 0）。
- **P2 超額命中：** `ΔX = X(E) − X(H)`。CI 下界大於 0 記「成立」，上界小於 0 記「不成立」，其餘記「持平」。
- **CI：** 以串流為單位配對、有放回抽樣 10,000 次，種子 `20261012`，取第 2.5 和 97.5 百分位。
- **結論：** 兩項都成立是「優於」，兩項都不成立是「不如」，一項成立一項不成立是「有得有失」，任一項持平就是「持平」。
- **主判定只看 injected 層**，因為只有這一層對兩個方法都是沒看過的串流。

## 二、背景與動機

**問題。** DET1 顯示，把 ECPF 的偵測器換成現成的 HDDM-A，誤報比原本的雙 ADWIN 少，命中也比較多。主方法 E10bFT 用四個自訂元件處理同一個問題，但 DET1、DET2 的正式比較都沒有納入它。主方法是否比一個現成、較簡單的偵測器好，沒有證據。

**為什麼要另開一輪。** 兩個方法唯一的既有重疊是五條 INSECTS，樣本太小，而且結果已經看過。injected 和 synthetic 上，主方法還沒有用 DET1 的計分跑過，所以先登記規則再跑。

**事前預測（登記時寫下）：**

- 主判定不預設方向。
- 主方法的風險在延遲：它在舊版注入 electricity 上從漂移到確認的時間比主窗長，警報可能落在窗外被算成誤報。
- H2：在 injected 的漸變漂移上，主方法的超額命中會比 HDDM-A 多。
- H3：兩組準確率持平。

## 三、實驗設計與流程

**比較基準。** DET3-H 用本機、本輪 commit 重跑的結果，不直接用 DET1 的存檔，讓兩組同機器、同程式碼。

**步驟（順序在登記時固定）：**

1. 提交 Windows 相容修正、預註冊、計分腳本與啟動腳本。
2. G1：在本輪 commit 上跑 electricity 的 `e10bft`，和 main 提交的結果逐欄比對。
3. 重跑 DET3-H 的 205 條，和 DET1 存檔的 A3 逐條比對（G2、G3）。
4. 跑 DET3-E 的 205 條，只跑一次。
5. 計分與 bootstrap。

**環境。** Windows 11，Python 3.9.12，numpy 1.26.4，pandas 2.3.3，river 0.21.2，6 個 worker，`PYTHONUTF8=1`。指令是 `scripts/run_det3.sh gate` 和 `scripts/run_det3.sh judge`。

**閘門。** G1 環境、G2 重現 HDDM-A、G3 計分一致、G4 兩組配對、G5 完整性。G2 若不完全相同，登記的處理方式是：列出差異、判定仍用本機重跑的 DET3-H、S3 改標「參考」。

**和 DET1 的差別。** 組別換成主方法對 HDDM-A；主判定母體縮小到 injected；多了三個敏感度分析（S1 去掉可能被試跑看過的串流、S2 把計分窗改成 2500 步、S3 對雙 ADWIN 和 RDDM）。

### 4.2 主判定：injected 160 條

| 量 | DET3-E | DET3-H | 差（E − H） | 95% CI | 狀態 |
|---|---:|---:|---:|---|---|
| FP | 110 | 84 | +26 | [0, +50] | P1 持平 |

**主判定結論：持平。** 依登記的意義，不能主張 E10bFT 的偵測優於 HDDM-A，論文必須把 HDDM-A 寫成效果相當、而且比較簡單的做法。

這個「持平」偏向不利的一側，要一起讀：

- P2 不成立：主方法的超額命中明確比 HDDM-A 少。
- P1 的 CI 下界剛好是 0，照規則記持平；點估計是主方法多 26 次誤報。
- 命中數是 35 對 44（各 160 個 GT），MDT 是 541 對 333 步。

結論的適用條件：單棵 Hoeffding Tree、警告期間暫停訓練、注入漂移的 electricity、1000 步主窗。

### 4.7 事後觀察（登記後才想到，不是判準）

- **主方法的落後主要是慢，不是抓不到。** injected 的計分窗從 1000 步放到 2500 步，主方法的命中從 35 增加到 69，FP 從 110 降到 71；HDDM-A 的命中從 44 增加到 60，FP 從 84 降到 64。主方法在 1000 步窗被算成誤報的警報，有 39 次落在漂移後 1000 到 2500 步之間。
- **主方法暫停訓練的時間長得多。** injected 上是 117,153 步對 14,313 步，約 8 倍，準確率沒有因此變差，也沒有變好。
- **class_prior 的突變上兩組都幾乎抓不到，** 但主方法多了 15 次誤報（18 對 3）。
- **跨平台不能逐位重現。** 同一條 injected 或 synthetic 串流，Mac 和 Windows 跑出的準確率可能在小數後幾位不同，偶爾連警報數也不同。raw electricity 和 INSECTS 不受影響。機制沒有確認。

## 五、局限性與衍生問題

**局限：**

- 只有一種學習器、一種來源資料集的注入漂移，結論不能推到森林、迴歸或其他真實資料。
- injected 每個 cell 只有 20 個 trial，每條一個漂移。主判定的 P1 落在邊界上，S1 去掉 24 條後就翻成不成立。
- 1000 步主窗是 DET1 和登記檔的設定。主方法原本的實驗用 3000 步窗，而且有 1000 步的警告逾時設計，這個窗對它不利。S2 顯示結論對窗長敏感，但 S2 是敏感度分析，不能拿來當作「主方法在 2500 步窗較好」的證據。
- HDDM-A 用 MOA 預設參數，主方法的參數在別的資料上定的，兩邊都沒有在這批串流上調參。
- S3 跨機器比較，只能當方向參考。
- DET3-H 沒有逐位重現 DET1 的存檔，本輪的 HDDM-A 數字和 DET1 表格略有出入。

**衍生問題：**

- 主方法的四個元件換來的是「比未處理的雙 ADWIN 好」，但 HDDM-A 不用這些元件就達到同等或更好的偵測，而且偵測得更快、暫停訓練的時間更短。
- 注入串流在不同作業系統上不能逐位重現，會影響組內標準實驗的跨機器比對。

**下一步（都還沒做）：**

1. 論文的偵測主張改寫：對象從「文獻偵測器」縮小為「未處理的雙 ADWIN」；HDDM-A 寫成效果相當、較簡單、較快的做法。
2. 若要主張「放寬計分窗後主方法較好」，需要另外登記一輪、用新的串流（例如 g20 之後的 trial 或另一個來源資料集），不能重用這 160 條。
3. 把跨平台差異回報給維護標準實驗流程的組員，並查明來源。
4. 若要保留主方法的元件，可以考慮「HDDM-A 的區間加上凍結參照」這類組合，但那是新設計，要先登記、用新資料。
